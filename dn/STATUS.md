## Завершённое (D1, подготовка D3)

1. **Исследование (D1):** `docs/DN-RESEARCH.md`
   - Версия DN: 1.51 (RIT Research Labs, 19 апреля 1999)
   - Лицензия: BSD-подобная с рекламным пунктом 
   - Исходники: `https://download.ritlabs.com/dn/dn151src.zip` (926 КБ)
   - 99 866 строк Pascal в 122 файлах; 10 файлов ASM
   - Пять файлов явно копируют уведомления Borland (OBJECTS, MEMORY, HISTLIST, STRINGS, VALIDATE)

2. **Структура проекта:** `dn/` каталог
   - `audit/` — результаты D3 (реестр, подготовка)
   - `specs/` — спецификации для D4
   - `detectors/` — три типа детекторов
   - `tv-clean/` — переписанный код (результат D4)

3. **Нормализатор кода:** `dn/detectors/normalize.py`
   - Удаление комментариев (`{...}`, `(*...*)`, `//...`)
   - Нормализация пробелов
   - Токенизация Pascal-кода
   - Приведение ключевых слов к единому регистру
   - Опция: замена идентификаторов на заглушки (для детекторов A, C)

4. **Три детектора совпадений:**
   - **A (k-граммы):** скользящее окно токенов, винноинг, хэши (как MOSS)
   - **B (построчное):** точные совпадения строк, расширение в блоки
   - **C (попроцедурное):** парсинг процедур, сравнение токенов, Jaccard-сходство

## В разработке

### D3 Аудит

**Что осталось:**
1. Контрольные данные для тестирования детекторов
   - `dn/detectors/test-data/positive/` — копии из TV с переименованием/переформатированием
   - `dn/detectors/test-data/negative/` — независимый код
   - `dn/detectors/test-data/expected.json` — ожидаемые результаты

2. Скрипт валидации тестов (`validate-tests.py`)
   - Проверка, что все детекторы находят положительные примеры
   - Проверка, что не срабатывают на отрицательных
   - Вывод: пороги для прогона по DN и TV

3. Скрипт подготовки (`audit/prep.py`)
   - Скачивание/проверка SHA256 исходников DN и TV
   - Нормализация и индексирование файлов
   - Сохранение подготовленных данных

4. Запуск детекторов на DN и TV
   - Три прогона (A, B, C) одновременно
   - Сбор результатов в единый JSON
   - Заполнение реестра `audit/register.csv`

## Следующие шаги (приоритет)

### Блокирующие D3 (эта неделя)

1. **Контрольные данные.** Создать две примеры процедур TV с трансформациями:
   - `test-data/positive/copied_with_rename.pas` (переименование переменных)
   - `test-data/positive/copied_reformatted.pas` (пробелы, переносы строк)
   - `test-data/negative/independent_list_search.pas` (собственная реализация)
   - Вручную проверить, что они действительно скопированы / независимы

2. **Валидация детекторов.** Написать `validate-tests.py`:
   - Запускает три детектора на контрольных данных
   - Проверяет, что срабатывают/не срабатывают как ожидается
   - Подбирает пороги автоматически

3. **Скрипт подготовки.** Написать `audit/prep.py`:
   - Загружает исходники DN и TV
   - Нормализует и индексирует
   - Готовит данные для детекторов

### D3 основной прогон (следующая неделя)

4. **Прогон детекторов.** `audit/run-audit.sh`:
   - Запускает все три детектора
   - Объединяет результаты
   - Генерирует начальную версию `register.csv`

5. **Ручной анализ результатов.** Для каждого срабатывания:
   - Проверить корректность (не ложноположительное ли?)
   - Решить: переписать / совпадение по интерфейсу / ложное
   - Записать в реестр с комментариями

### D2 Характеризационные тесты (параллельно D3)

Сценарии с `<waitfor:…>` для основных экранов:
- Панели файлов
- Меню операций
- Диалог создания папки
- Просмотр файла
- Редактор текста

## Ограничения и риски

| Риск | Вероятность | Влияние | План |
|------|------------|--------|------|
| Исходники TV недоступны | Низкая | Высокое | Использовать Free Vision или реконструировать из документации |
| Детекторы дают слишком много ложноположительных | Средняя | Среднее | Подбор порогов на контрольных данных, ручная проверка |
| D4 переписка требует больше времени, чем ожидается | Средняя | Высокое | Распараллелить на несколько процедур в разных сессиях |
| Поведение NC отличается от DN | Низкая | Среднее | Использовать характеризационные тесты для валидации |
