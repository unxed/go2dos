# Детекторы совпадений кода (аудит D3)

Три независимых метода поиска заимствований из Turbo Vision в Dos Navigator 1.51.

## Детектор A: k-граммы токенов с винноингом

Аналогично MOSS (Moss Similarity Score). Процесс:

1. Нормализация исходников:
   - Удаление комментариев и пробелов
   - Приведение идентификаторов к единому регистру
   - Регулярное выражение на токены (слова, операторы, скобки)

2. Замена идентификаторов на заглушки (ловит копии с переименованием)

3. Скользящее окно k-грамм (k зависит от языка; для Pascal начать с k=5)

4. Вычисление хэшей отпечатков

5. Сравнение множеств хэшей между всеми парами файлов

6. Порог срабатывания: минимальная длина общей последовательности в токенах (подбирается на контрольных данных)

## Детектор B: построчное сравнение

Сравнение текста без комментариев и пробельных различий:

1. Нормализованный текст каждого файла — строка за строкой
2. Точное совпадение строк между DN и TV
3. Расширение совпадений в блоки (连续 совпадения)
4. Вывод: диапазоны строк с идентичным кодом

## Детектор C: попроцедурное сравнение

Сравнение процедур и методов:

1. Парсинг Pascal, выделение каждой процедуры/функции/метода
2. Для каждой процедуры DN:
   - Токенизация (с заменой идентификаторов)
   - Поиск ближайшей процедуры TV по той же сигнатуре (если есть)
   - Вычисление меры сходства (например, доля совпадающих токенов)
3. Вывод: пары процедур с мерой сходства

## Контроль детекторов (шаг 4 в DN-PLAN.md)

Перед прогоном по DN все три детектора проверяются на контрольных данных:

1. **Положительный тест:** заведомая копия процедуры TV (с переименованием и переформатированием) должна находиться с высокой мерой сходства

2. **Отрицательный тест:** заведомо независимый код не должен срабатывать детекторов

Процедура описана в `detectors/test-detectors.md`.
