# vc-wasm: ручной (LLM) перевод Volkov Commander в WebAssembly

Статус: эксперимент, итерация 3 — ревью концепции, переход с WAT на C (wasm
остаётся артефактом), план для исполнителя: **`PLAN.md`**. К эмулятору go2dos
на Go не относится; живёт в этом репозитории, пока для него рано заводить свой.
Код в `src/` и `c/` — производная работа от исходников VC (BSD-2-Clause,
© Vsevolod Volkov); текст лицензии — `LICENSE-VC.TXT` (переведён CRLF → LF).

## Идея

Исходники VC открыты, поэтому программу можно не эмулировать и не
транслировать автоматически, а **переписать в wasm**: модель (LLM) читает
ассемблер процедуры за процедурой и пишет эквивалентный код (с итерации 3 —
на C, который clang собирает в wasm; до неё — WAT). Wasm здесь —
универсальный промежуточный формат: из него `wasm2c`/`w2c2` и обычный
C-компилятор дают нативный код под любое 32-битное железо, а тот же модуль
работает в браузере и под WASI. Рантайм wasm на целевом железе не нужен.

## Чем это отличается от `docs/TRANSLATION.md`

| | `docs/TRANSLATION.md` (M13) | `vc-wasm/` |
|---|---|---|
| Как получаем wasm | автоматический транслятор x86 → wasm на Go по метаданным JWasm | ручной перевод исходников моделью |
| Что сопровождаем | транслятор | сам перевод как код (C) |
| Проверка | прогоны в go2dos | те же прогоны (итерация 2: CPU go2dos как эталон) |

Это не вторая реализация одной задачи, а другой способ получить тот же артефакт
(по поручению владельца). Общий эталон поведения — CPU go2dos на настоящем
`VC.COM`.

## Установлено (grep по `versions/4.05`, регулярные выражения приблизительные)

- Около 33,8 тыс. строк asm (`VC.ASM`, `VCSETUP.ASM`, `*.INC`), модель Tiny, один `.COM`.
- Места вызова: `INT 21h` — 141, `INT 10h` — 95, `INT 16h` — 34, `INT 33h` — 14.
  Команд `IN`/`OUT` нет. Видеосегмент (B800h/B000h) выбирается в двух местах.
- Настоящих косвенных `JMP`/`CALL` 12: таблицы `FncAddr`, `Country.CaseMap`
  (вызов в код самой DOS), цепочка `CS:Vect27`.

## Соглашения перевода

D1–D6 относятся к замороженному WAT (`src/vcsub1.wat`). Правила для C — `PLAN.md`, §3.

- **D1. Память:** один wasm-линейный блок; сегмент tiny-модели — `0x0000–0xFFFF`,
  окно текстового экрана (B800h) — с `0x10000`. Сегмент обращения (`ES:`) —
  параметр `$es` (его значение — база в линейной памяти).
- **D2. Регистры:** читаемые процедурой — параметры, меняемые и видимые
  вызывающему — результаты (multi-value), `CF` — последний результат. Всё, что
  процедура сохраняет через `PUSH/POP`, в результаты не входит.
- **D3. Флаги** вычисляются только там, где код их потом читает.
- **D4. Переходы** — структурные `block/loop`; без диспетчера базовых блоков.
- **D5. Единица перевода:** один `.wat` на один исходный `.INC`/`.ASM`; имена
  функций — имена процедур в нижнем регистре; в комментариях — исходные
  команды ассемблера рядом с переведённым кодом.
- **D6. Особенности оригинала сохраняются** (например, насыщение числа в
  `TxtNum`), а не «исправляются».

## Запуск тестов

```sh
pip install wasmtime          # проверено на 49.0.0
sh vc-wasm/c/build.sh         # clang + wasm-ld (проверено на LLVM 18): c/build/vc.wasm
python3 -m unittest discover -s vc-wasm/tests -v
```

Векторы эталона (`oracle/vectors.json`, закоммичены) перегенерируются из
настоящего `VC.COM` (нужен Go из `go.mod`):

```sh
sh tools/fetch-vc.sh .cache/vc
go run ./vc-wasm/oracle -com .cache/vc/4.05/VC.COM -out vc-wasm/oracle/vectors.json
python3 vc-wasm/tools/sizes.py .cache/vc/4.05/VC.COM    # метрика размера
```

В CI Python-тесты не подключены (отдельный патч по слову владельца);
`oracle/` — обычный пакет корневого модуля, его собирает `go build ./...`.

## Метрика размера (итерация 2, **установлено** запуском)

Тела функций, байты; x86 — из `VC.COM`, wasm — секция кода `vcsub1.wat` как есть
(без `wasm-opt`, WAT написан вручную):

| Процедура | x86 | wasm | wasm/x86 |
|---|---|---|---|
| `HexCod` | 13 | 51 | 3,92 |
| `HexByt` | 15 | 28 | 1,87 |
| `TxtNum` | 49 | 137 | 2,80 |
| итого | 77 | 216 | 2,81 |

Оговорки: выборка из трёх процедур; размер wasm-байткода не равен размеру
нативного кода после `wasm2c` + `clang -Os` (это итерация 3); на малых
процедурах давят постоянные накладные расходы (константы `i32` занимают по
2–3 байта, маски 16 бит видны явно).

## Ревью концепции (итерация 3, 01-10-2026)

**Подтвердилось** (установлено по исходникам и запуском):

- Исходник 4.05 годится для механического перевода: портов нет, самомодификации
  кода нет (шесть записей через `CS:` — данные: `RunPar`, блок параметров
  `OvlPrm` для EXEC, таблица сегментов блоков памяти, поля PSP), косвенных
  переходов 12 — через таблицы.
- Листинг JWasm из pts-vc405-port даёт адрес и байты каждой команды и таблицу
  меток, а сборка с листингом побайтно равна эталону TASM. Значит, перевод можно
  сверять с бинарником адрес в адрес.
- CPU go2dos годится как эталон (итерация 2), а в `machine` уже есть точки
  останова (`cpu.BreakAt`, `cpu.Break`) для сверки «по процедурам» на живом VC.

**Пересмотрено:**

1. **WAT → C** (wasm остаётся артефактом): w2c2 не принимает функции с
   несколькими результатами (установлено: `unsupported function type 0 with 2
   result values`), на которых держалось соглашение D2; переходы ассемблера
   ложатся на `goto` C один к одному, а WAT требует восстанавливать структуру
   (это делает за нас clang); в VC есть переходы в середину чужой процедуры
   (`Numb10` → `Numb21` внутри `Numb20`), которые схема «процедура = функция с
   параметрами» не выражает. Перевод в C сверен с теми же векторами, что WAT, —
   совпадает (`tests/test_c_oracle.py`).
2. **Регистры — глобальное состояние**, а не параметры: перевод механический,
   анализ контракта нужен только для флагов.
3. **Данные не переводятся**: начальная память — образ `VC.COM` (смещения
   переменных, таблиц и строк — исходные).
4. **«64 КБ» после перевода не сохраняется.** Тела функций, байты (Cortex-M4 —
   `clang --target=thumbv7em-none-eabi -mcpu=cortex-m4 -Os`; w2c2 — HEAD
   01-10-2026; «доступ» — общие функции памяти и стека, разовые):

   | Вариант | HexCod | HexByt | TxtNum | Σ | доступ |
   |---|---|---|---|---|---|
   | x86 (`VC.COM`) | 13 | 15 | 49 | 77 | — |
   | WAT вручную → wasm | 51 | 28 | 137 | 216 | — |
   | C `-Os` → wasm | 138 | 757 | 1174 | 2069 | встроен |
   | C `-Oz -DVC_SMALL` → wasm | 134 | 147 | 454 | 735 | 345 |
   | C `-Os` → wasm → w2c2 → Cortex-M4 | 230 | 1026 | 1500 | 2756 | встроен |
   | C `VC_SMALL` → wasm → w2c2 → Cortex-M4 | 260 | 266 | 854 | 1380 | 538 |
   | C `-Os` → Cortex-M4 напрямую | 92 | 406 | 682 | 1180 | встроен |
   | C `-Oz VC_SMALL` → Cortex-M4 напрямую | 64 | 76 | 196 | 336 | 220 |

   На трёх процедурах код растёт в 4,4 раза (C напрямую) и в 18 раз (через wasm
   и w2c2) относительно x86. Слой wasm стоит около 4 раз — это цена
   концепции «wasm как универсальный промежуточный формат». Экстраполяция на
   весь VC (процедуры лежат в `040A–CBC4`, около 51 КБ вместе с данными
   между ними) — **предположение**: 0,2–0,9 МБ нативного кода.
   Класс целей — 32-битные МК с ≥ 256 КБ ОЗУ и ≥ 1 МБ флеша (RP2040, ESP32);
   ОЗУ определяется ареной (VC сам по себе занимает 64 КБ плюс буферы), её
   минимальный размер не измерен. Ручки размера (`VC_SMALL`, позже регистры в
   локальных переменных) — только в `vc.h`, после корректности.

**Главные риски:** объём (276 процедур и 2548 меток, 1965 `CALL`; трудоёмкость
не измерена — первые волны её покажут), DOS-слой и терминал поверх WASI
(опрос stdin через `poll_oneoff`, raw-режим терминала).

Метод замера: `clang` 18.1.3 из песочницы, `w2c2` собран CMake, заголовки
libc для thumbv7em — заглушки (в модулях нет плавающей точки); размеры —
`llvm-nm -S`, для wasm — секция кода и секция имён.

## Состояние

| Процедура (`versions/4.05/VCSUB1.INC`) | WAT (заморожен) | C (`c/vcsub1.c`) | Сверка с `VC.COM` 4.05 |
|---|---|---|---|
| `HexCod` | `hexcod` | `HexCod` | совпадает на 512 векторах (все AL × DI ∈ {0, 0xFFFF}) |
| `HexByt` | `hexbyt` | `HexByt` | совпадает на 1024 векторах (все AL × 4 значения DI, включая переход через 64 КиБ) |
| `TxtNum` | `txtnum` | `TxtNum` | совпадает на 2219 векторах (насыщение, CF, строки до 3 символов над смешанным алфавитом, случайные) |

Оба перевода (WAT и C) проверяются на одних векторах.

«Совпадает» значит: выходные AX/AL, SI/DI, CF и изменённые байты памяти равны
результату настоящего кода в CPU go2dos; сохранность BX/CX/DX/AH оракул
проверяет сам. Флаги на выходе `HexCod`/`HexByt` оракул не записывает.

## Сомнения

- **WAT или C** — решено в пользу C (ревью, п. 1; `PLAN.md`, R1).
- **Multi-value** — **установлено**: w2c2 не принимает. Сборка C в wasm их не
  порождает.
- **Флаги на выходе `HexCod`/`HexByt`** не моделируются; по местам вызова не
  проверено, читает ли их кто-нибудь (в C это проверяет правило П4 `PLAN.md`).
- **`DF=0`** в WAT предполагается; перевод в C учитывает DF (`vc.h`, П7).
- **Трудоёмкость:** оценка для всего VC 4.05 не делалась.
