# vc-wasm: ручной (LLM) перевод Volkov Commander в WebAssembly

Статус: эксперимент, итерация 5 — модель перевода в WAT согласована с
владельцем (регистры — глобальные переменные, переходы — диспетчер по меткам,
данные — из исходника), согласована схема запуска (интерфейс модуля — сам DOS,
экран — память, шоукейс — go2dos с `vc.wasm` вместо CPU), план для
исполнителя: **`PLAN.md`**. К эмулятору go2dos
на Go не относится; живёт в этом репозитории, пока для него рано заводить свой.
Код в `src/` — производная работа от исходников VC (BSD-2-Clause,
© Vsevolod Volkov); текст лицензии — `LICENSE-VC.TXT` (переведён CRLF → LF).

## Идея

Исходники VC открыты, поэтому программу можно не эмулировать и не
транслировать автоматически, а **переписать в wasm**: модель (LLM) читает
ассемблер процедуры за процедурой и пишет эквивалентный WAT. Wasm здесь —
универсальный промежуточный формат: из него получается нативный код под любое
32-битное железо, а тот же модуль работает в браузере и под WASI. Рантайм
wasm на целевом железе не нужен.

## Чем это отличается от `docs/TRANSLATION.md`

| | `docs/TRANSLATION.md` (M13) | `vc-wasm/` |
|---|---|---|
| Как получаем wasm | автоматический транслятор x86 → wasm на Go по метаданным JWasm | ручной перевод исходников моделью |
| Что сопровождаем | транслятор | сам WAT как код |
| Проверка | прогоны в go2dos | те же прогоны (итерация 2: CPU go2dos как эталон) |

Это не вторая реализация одной задачи, а другой способ получить тот же артефакт
(по поручению владельца). Общий эталон поведения — CPU go2dos на настоящем
`VC.COM`.

## Установлено (grep по `versions/4.05`, регулярные выражения приблизительные)

- Около 33,8 тыс. строк asm (`VC.ASM`, `VCSETUP.ASM`, `*.INC`), модель Tiny, один `.COM`.
- Места вызова: `INT 21h` — 141, `INT 10h` — 95, `INT 16h` — 34, `INT 33h` — 14.
  Команд `IN`/`OUT` нет. Видеосегмент (B800h/B000h) выбирается в двух местах.
- Настоящих косвенных `JMP`/`CALL` 12: таблицы `FncAddr`, `Country.CaseMap`
  (вызов в код самой DOS), цепочка `CS:Vect27`.

## Соглашения перевода

Действующие правила — `PLAN.md`, §3; образец — `src/rt.wat` и `src/vcsub1.wat`.
Соглашения итераций 1–2 (D1–D6) ниже сохранены для истории: D1, D2 и D4
заменены (итерация 4, согласовано с владельцем 01-10-2026), D3, D5 и D6
вошли в правила.

- **D1. Память:** один wasm-линейный блок; сегмент tiny-модели — `0x0000–0xFFFF`,
  окно текстового экрана (B800h) — с `0x10000`. Сегмент обращения (`ES:`) —
  параметр `$es` (его значение — база в линейной памяти).
- **D2. Регистры:** читаемые процедурой — параметры, меняемые и видимые
  вызывающему — результаты (multi-value), `CF` — последний результат. Всё, что
  процедура сохраняет через `PUSH/POP`, в результаты не входит.
- **D3. Флаги** вычисляются только там, где код их потом читает.
- **D4. Переходы** — структурные `block/loop`; без диспетчера базовых блоков.
- **D5. Единица перевода:** один `.wat` на один исходный `.INC`/`.ASM`; имена
  функций — имена процедур в нижнем регистре; в комментариях — исходные
  команды ассемблера рядом с переведённым кодом.
- **D6. Особенности оригинала сохраняются** (например, насыщение числа в
  `TxtNum`), а не «исправляются».

## Запуск тестов

```sh
pip install wasmtime          # проверено на 49.0.0
python3 vc-wasm/tools/build.py                       # склейка src/*.wat -> build/vc.wasm
python3 -m unittest discover -s vc-wasm/tests -v     # тесты собирают модуль сами
```

Векторы эталона (`oracle/vectors.json`, закоммичены) перегенерируются из
настоящего `VC.COM` (нужен Go из `go.mod`):

```sh
sh tools/fetch-vc.sh .cache/vc
go run ./vc-wasm/oracle -com .cache/vc/4.05/VC.COM -out vc-wasm/oracle/vectors.json
python3 vc-wasm/tools/sizes.py .cache/vc/4.05/VC.COM    # метрика размера
```

В CI Python-тесты не подключены (отдельный патч по слову владельца);
`oracle/` — обычный пакет корневого модуля, его собирает `go build ./...`.

## Метрика размера (итерация 2, модель D1–D6, **установлено** запуском)

Тела функций, байты; x86 — из `VC.COM`, wasm — секция кода `vcsub1.wat` как есть
(без `wasm-opt`, WAT написан вручную):

| Процедура | x86 | wasm | wasm/x86 |
|---|---|---|---|
| `HexCod` | 13 | 51 | 3,92 |
| `HexByt` | 15 | 28 | 1,87 |
| `TxtNum` | 49 | 137 | 2,80 |
| итого | 77 | 216 | 2,81 |

Оговорки: выборка из трёх процедур; размер wasm-байткода не равен размеру
нативного кода; на малых процедурах давят постоянные накладные расходы
(константы `i32` занимают по 2–3 байта, маски 16 бит видны явно).

## Ревью концепции (итерации 3–4, 01-10-2026)

**Подтвердилось** (установлено по исходникам и запуском):

- Исходник 4.05 годится для механического перевода: портов нет, самомодификации
  кода нет (шесть записей через `CS:` — данные: `RunPar`, блок параметров
  `OvlPrm` для EXEC, таблица сегментов блоков памяти, поля PSP), косвенных
  переходов 12 — через таблицы.
- Листинг JWasm из pts-vc405-port даёт адрес и байты каждой команды и таблицу
  меток, а сборка с листингом побайтно равна эталону TASM. Значит, перевод можно
  сверять с бинарником адрес в адрес.
- CPU go2dos годится как эталон (итерация 2), а в `machine` уже есть точки
  останова (`cpu.BreakAt`, `cpu.Break`) для сверки «по процедурам» на живом VC.

**Пересмотрено** (согласовано с владельцем 01-10-2026):

1. **Регистры и флаги — глобальные переменные wasm**, процедура — функция без
   результатов. Причина: w2c2 не принимает функции с несколькими результатами
   (установлено: `unsupported function type 0 with 2 result values`), на
   которых держалось D2. Модель с глобальными w2c2 принимает (установлено;
   предупреждает только, что не умеет экспортировать глобальные — экспорт
   нужен лишь тестам и харнессу).
2. **Переходы — диспетчер по меткам** (`loop` + `br_table`, номер метки —
   параметр функции). Причина: механичность и переходы в середину чужой
   процедуры (`Numb10` → `Numb21` внутри `Numb20`), которые схема D4 не
   выражает.
3. **Данные переносятся из исходника** в сегменты данных WAT по исходным
   смещениям; бинарник `VC.COM` с модулем не поставляется (`PLAN.md`, R4).
4. **Интерфейс модуля — сам DOS** (итерация 5): единственный импорт
   `vc.int(n)` с кадром `INT` и регистровым блоком, экран — видеопамять
   `B800`, шоукейс — go2dos с `vc.wasm` вместо CPU (`PLAN.md`, R8–R10).
   Отклонены: DOS и терминал внутри модуля поверх WASI (много WAT, не
   относящегося к VC; терминал вшит даже там, где экран — LCD; WASI на МК
   тяжелее подмножества `INT 21h` над FatFS) и свой «урезанный DOS» внутри
   модуля (самодельный интерфейс вместо документированного).

**Размер.** Тела функций, байты (Cortex-M4 — `clang --target=thumbv7em-none-eabi
-mcpu=cortex-m4 -Os` по выходу w2c2, w2c2 — HEAD 01-10-2026; «rt» — общие
функции `rt.wat`, разовые):

| Вариант | HexCod | HexByt | TxtNum | Σ | rt |
|---|---|---|---|---|---|
| x86 (`VC.COM`) | 13 | 15 | 49 | 77 | — |
| WAT D1–D6 (итерация 2) → wasm | 51 | 28 | 137 | 216 | — |
| WAT, модель итерации 4 → wasm | 71 | 54 | 242 | 367 | 477 |
| WAT, модель итерации 4 → w2c2 → Cortex-M4 | 60 | 154 | 330 | 544 | 730 |

На трёх процедурах нативный код примерно в 7 раз больше x86. Экстраполяция на
весь VC (процедуры лежат в `040A–CBC4`, около 51 КБ вместе с данными между
ними) — **предположение**: порядка 350 КБ кода. «64 КБ» после перевода не
сохраняется; класс целей — 32-битные МК с ≥ 256 КБ ОЗУ и ≥ 1 МБ флеша
(RP2040, ESP32), минимальный размер памяти для VC не измерен.

**Главные риски:** объём (276 процедур и 2548 меток, 1965 `CALL`; трудоёмкость
не измерена — первые волны её покажут); минимум памяти, с которым работает VC,
не измерен (`PLAN.md`, D5) — ниже примерно 128 КБ ОЗУ VC не поместится при
любом подходе (**предположение**: данные разбросаны по смещениям одного
сегмента 64 КБ, плюс буферы панелей).

Метод замера: `w2c2` собран CMake; заголовки libc для thumbv7em — заглушки (в
модуле нет плавающей точки); размеры — `llvm-nm -S`, для wasm —
`tools/sizes.py` (секция кода и секция имён).

## Состояние

| Процедура (`versions/4.05/VCSUB1.INC`) | WAT (`src/vcsub1.wat`) | Сверка с `VC.COM` 4.05 |
|---|---|---|
| `HexCod` | `$HexCod` | совпадает на 512 векторах (все AL × DI ∈ {0, 0xFFFF}) |
| `HexByt` | `$HexByt` | совпадает на 1024 векторах (все AL × 4 значения DI, включая переход через 64 КиБ) |
| `TxtNum` | `$TxtNum` | совпадает на 2219 векторах (насыщение, CF, строки до 3 символов над смешанным алфавитом, случайные) |

«Совпадает» значит: выходные AX/AL, SI/DI, CF и изменённые байты памяти равны
результату настоящего кода в CPU go2dos; сохранность BX/CX/DX/AH оракул
проверяет сам. Флаги на выходе `HexCod`/`HexByt` оракул не записывает.

## Сомнения

- **Multi-value** — **установлено**: w2c2 не принимает; модель итерации 4 их не
  использует.
- **Экспорт глобальных** — **установлено**: w2c2 не поддерживает (предупреждение,
  модуль собирается). Нужен только тестам и харнессу.
- **Флаги на выходе `HexCod`/`HexByt`** не моделируются; по местам вызова не
  проверено, читает ли их кто-нибудь (правило П7 `PLAN.md`).
- **Трудоёмкость:** оценка для всего VC 4.05 не делалась.
