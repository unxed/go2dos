# vc-wasm: план для исполнителя

Для модели, которая продолжит работу (Sonnet/Haiku). Цель документа: чтобы на
каждом шаге было ясно, **что делать, как проверить и когда остановиться**, без
вопросов владельцу. Составлен 01-10-2026 по итогам ревью (README, «Ревью
концепции»). Факты в нём помечены **установлено** (проверено запуском или по
исходникам), остальное — решения, их не пересматривать без владельца.

Прочитай перед началом: `AGENTS.md` (правила работы с владельцем — они
действуют и здесь), `vc-wasm/README.md`, этот файл целиком, `vc-wasm/c/vc.h`,
`vc-wasm/c/vcsub1.c` (образец перевода).

## 0. Цель, границы, принятые решения

**Цель.** `vc.wasm` — Volkov Commander 4.05, переведённый моделью из
ассемблера в C и собранный в wasm32. Запускается `wasmtime` в терминале; тот же
`vc.wasm` через w2c2 даёт C и нативную сборку под другое железо.

**Не делаем** (до слова владельца): запуск программ (`EXEC`, `4B00h`) и
выгрузку VC из памяти, мышь (`INT 33h` отвечает «драйвера нет»), `VCSETUP`,
VC 4.99.09, EMS, оптимизацию размера (кроме ручек в `vc.h`), любые «улучшения»
поведения VC.

**Решения** (обоснование — README, «Ревью концепции»):

- **R1. Язык перевода — C** по правилам §3, сборка `clang --target=wasm32`.
  `src/vcsub1.wat` заморожен как исторический образец: не развивать, не удалять.
- **R2. Источник — `vc.asm` из pts-vc405-port** на коммите `PTS_COMMIT`
  (`third_party/vc/PINS`): он побайтно собирается в эталонный `VC.COM`
  (**установлено**, `tools/build-vc405-pts.sh`). Адреса берутся из листинга
  JWasm (§2).
- **R3. Данные не переводятся.** Начальное содержимое памяти — образ `VC.COM`,
  загруженный в `PSP:0100`, как это делает DOS. Переводится только код; таблицы,
  строки и переменные лежат по своим исходным смещениям.
- **R4. Состояние — глобальное**: регистровый файл `r` и арена — 1 МиБ
  адресного пространства реального режима (`vc.h`). Процедура — функция
  `void Name(void)`.
- **R5. Хост-интерфейс боевой сборки — только WASI preview1**: прямые импорты
  `wasi_snapshot_preview1` без wasi-libc. DOS-слой (`INT 21h/10h/16h`) и
  терминал (ANSI на fd 1, клавиши с fd 0) написаны на C внутри модуля.
- **R6. Эталон поведения — настоящий `VC.COM` в CPU go2dos** (§4). Семантика
  команд и флагов в спорных местах — как в `cpu/alu.go`, а не «по памяти».
- **R7. Натив — через wasm → w2c2 → C** (концепция владельца). Прямая сборка
  C → натив делается только как контрольный замер.
- **R8. Всё живёт в `vc-wasm/`.** Корневой модуль go2dos и его `go.mod` не
  трогать; Go-код с новыми зависимостями — во вложенном модуле
  `vc-wasm/lockstep/`.

## 1. Цикл одной сессии

1. Свежий клон `github.com/unxed/go2dos`, чтение файлов из шапки.
2. Взять первый незакрытый шаг из таблицы §8.
3. Сделать его вместе с тестами и правкой документации (§8, README «Состояние»).
4. Прогнать то, что относится к `vc-wasm` (сборка, `unittest`, харнесс).
   Полные наборы go2dos (`go test ./...`) — дело CI, не сессии.
5. Отдать **один патч для `git am`** поверх `master`, проверив `git am` на
   свежем клоне (AGENTS.md). Размер: один шаг §8; волна перевода — 10–25
   единиц или до ~1500 строк C.

Логи и отчёты делай компактными: одна строка на событие, не больше 20 строк
расхождений за прогон (владелец кормит логи моделям).

## 2. Этап A: листинг и карта единиц перевода

**A1. `vc-wasm/tools/listing.sh [OUTDIR]`** (по умолчанию `.cache/vc-wasm`):
вызывает `tools/build-vc405-pts.sh OUTDIR` (он клонирует pts-vc405-port и
проверяет эталон), затем в `OUTDIR/pts-vc405-port`:

```sh
./tools/jwasm-2.11a.upx -q -Cp -WX -e999999999 -bin -Fo"$OUT/VC.COM" -Fl"$OUT/vc.lst" vc.asm
```

и сверяет SHA-256 `$OUT/VC.COM` с `REF_405_VC_COM` из `third_party/vc/PINS`.
**Установлено:** с `-Fl` байты `VC.COM` те же.

**A2. `vc-wasm/tools/symbols.py OUTDIR/vc.lst`** пишет (коммитятся):

- `vc-wasm/data/units.json` — единицы перевода (правило ниже);
- `vc-wasm/c/sym.h` — `#define S_<метка> 0x<адрес>` для всех меток и
  переменных и `#define F_<Структура>_<поле> 0x<смещение>` для полей структур.

Формат листинга (**установлено** на `vc.lst`):

- файл содержит байты ≥ 80h (строки в CP866): читать как latin-1;
- строка команды: `^([0-9A-F]{8})  ([0-9A-F]+)?\s+\t?(исходный текст)`.
  Адрес — первые 8 цифр; байты команды — второе поле. У некоторых команд байты
  не напечатаны (например, `RET` по `A48B` внутри `HexByt`): длину вычисляй как
  разность со следующим адресом;
- таблицы в конце: `Macros:`, `Structures and Unions:`,
  `Procedures, parameters and locals:` (строки вида
  `HexByt . . . P Near A47D _TEXT Public`, одна FAR: `New27 . . . P Far 04FC`),
  `Symbols:` (метки: `Numb21 . . . L Near A470h _TEXT`);
- **установлено:** 276 процедур, 2548 меток, 1965 команд `CALL`, 196 команд
  `INT`; процедуры лежат в `040A–CBC4`, код до `040A` (вход `Zero` по `0100`)
  — вне `PROC`.

**Правило единиц** (вычисляет скрипт, не исполнитель):

1. Каждая `PROC … ENDP` — единица с именем процедуры.
2. Код вне `PROC` делится на единицы по меткам, которые являются целями `CALL`,
   плюс по адресу `0100` (`Zero`); единица — от такой метки до следующей
   границы.
3. **Входы единицы** — её начало и все метки внутри неё, на которые есть
   `CALL`/`JMP`/`Jcc` из других единиц.
4. Строки данных (`DB/DW/DD` между командами) помечаются `data`: они не
   переводятся (R3).

Формат `units.json`:

```json
{"units": [{"name": "Numb20", "start": "A467", "end": "A476", "far": false,
  "entries": ["Numb20", "Numb21"], "src": [12345, 12360],
  "callees": ["..."], "out_jumps": ["..."]}]}
```

`src` — строки `vc.asm`. `callees`/`out_jumps` — статические цели `CALL` и
переходов из единицы.

**A3. `vc-wasm/tools/progress.py`** печатает: всего единиц, переведено (по
заголовкам в `c/*.c`, формат П2), проверено (по `vc-wasm/data/verified.txt`
из харнесса, §4). Цифры из него — в таблицу §8.

**A4. `vc-wasm/tools/gen_dispatch.py`** пишет `c/dispatch.c`: функцию
`int vc_dispatch(uint16_t addr)`, где `switch` по адресу входа вызывает
единицу (или её вход, П5) и возвращает 0. Неизвестный или непереведённый адрес
даёт `-1`. Входы берутся из `units.json`; переведённые — по заголовкам `c/*.c`.

Готово, когда: листинг воспроизводится, `units.json` и `sym.h` сгенерированы,
у единицы `HexByt` вход `A47D`, у `TxtNum` — `A4B4` (сверка с
`oracle/vectors.json`), сумма длин всех единиц плюс данные покрывает
`0100…конец` без дыр (тест в `tests/`).

## 3. Правила перевода (П1–П16)

Образец всех правил — `c/vcsub1.c`.

- **П1. Файлы.** Единицы из `VCxxx.INC` идут в `c/vcxxx.c`, из `VC.ASM` — в
  `c/vc.c` (принадлежность — по `ddanila/vc versions/4.05`: где стоит `PROC`).
  Код вне `PROC` — в `c/vc.c`.
- **П2. Заголовок единицы** — ровно в таком формате (его читают скрипты):

  ```c
  /* A47D HexByt PROC NEAR
   * Вход: AL; ES:DI, DF.  Выход: AL, DI.  Флаги-выход: —.  Сохраняет: AH, CX. */
  ```

  Первая строка: `^/\* ([0-9A-F]{4}) (\w+) PROC (NEAR|FAR)`; у кода вне `PROC`
  тоже пиши `PROC NEAR`. Строка `Флаги-выход:` обязательна (П4).
- **П3. Одна команда — одна-две строки C**, исходная команда в комментарии
  справа, порядок команд сохраняется. Метки — метки C, переходы — `goto`.
  Никакого восстановления циклов, `if/else`, переименований. Пустые команды
  (`NOP`) тоже пиши комментарием.
- **П4. Флаги.** Вычисляй флаг только там, где его читают, прежде чем
  перезаписать: `Jcc`, `ADC/SBB`, `RCL/RCR`, `CMC`, `LAHF`, `PUSHF`, `LOOPZ`,
  `SALC`, и **вызывающий после возврата**. Выходные флаги единицы определяй так:
  для каждой точки `CALL` на неё (поиск по листингу) смотри команды после
  возврата до первой, которая перезаписывает флаг; читаемые там флаги — выход.
  Запиши их в `Флаги-выход:` и выставляй через `SETF` перед каждым выходом.
  Сравнение+переход пиши прямо на операндах: `CMP AX,BX / JB L` даёт
  `if (r.ax < r.bx) goto L;`, знаковые (`JL/JG/JLE/JGE`) — через `(int16_t)`.
  **Ловушки 8086:** `INC/DEC` не меняют CF; `MOV`, `LEA`, `XCHG`, `PUSH/POP`
  флаги не трогают; сдвиг на CL=0 флаги не меняет; счётчик сдвига не
  маскируется (8086). Где сомневаешься — читай `cpu/alu.go`.
- **П5. Вызовы и переходы между единицами.**
  - `CALL X` даёт `CALL(X, 0xNEXT)`, где NEXT — адрес следующей команды из
    листинга. `RET` даёт `RET()`, `RET n` — `RETN(n)`, `RETF` — `RETF()`,
    `CALL FAR` — `CALLF(X, seg, 0xNEXT)`.
  - `JMP X` в другую единицу — `TAILJMP(X)`; условный — `if (…) TAILJMP(X);`.
  - Конец единицы без `RET/JMP` (проваливание в следующую) — `TAILJMP(Next)`.
  - **Вход в середину единицы.** Если у единицы U больше одного входа, пиши
    `void U_at(int e)` с `switch (e) { case 0: break; case 1: goto L1; … }` в
    начале, плюс обёртки `void U(void) { U_at(0); }` и
    `void U_L1(void) { U_at(1); }`. Номера — по порядку в `entries`.
    Вызовы и переходы на `L1` идут в `U_L1`.
- **П6. Косвенные `CALL/JMP`** (`CALL DS:FncAddr`, `JMP [BX+tbl]`):
  `if (vc_dispatch(адрес)) TRAP();` (для `CALL` — с `PUSH(0xNEXT)` до и без
  `POP` после: `RET` вызванной единицы снимет адрес сам). Дальний вызов в чужой
  сегмент (`Country.CaseMap` — подпрограмма DOS) — `vc_far(seg, off)`, её
  реализует DOS-слой (§6) или харнесс (§4).
- **П7. Строковые команды** — только через помощников `vc.h` (`STOSB`,
  `LODSB(seg)`, …), они учитывают DF. Недостающие (`MOVS`, `CMPS`, `SCAS`,
  `REP`/`REPE`/`REPNE`) добавь в `vc.h` по образцу (`REP` — цикл по CX до 0, CX
  уменьшается). Приёмник — всегда ES, источник — DS или префикс.
- **П8. Память** — только `rb/wb/rw/ww(seg, off)`. Сегмент по умолчанию — DS;
  с `BP` в адресе — SS; префикс (`ES:`, `CS:`) — как в исходнике.
  Смещения и непосредственные значения — именами из `sym.h`
  (`S_Country + F_Country_Sep1000`). **Сверка с байтами:** число, которое
  получилось в C, должно совпасть со смещением в байтах команды из листинга.
  Не совпало — ты ошибся в адресации.
- **П9. Регистры** — поля `r`; половинки через `AL()/SET_AL()` и т.п.
  Сегментные регистры — просто `r.es = …`.
- **П10. `vc.h`** — единственное место для ручек скорости и размера
  (`VC_SMALL`, способ доступа к памяти). Переведённый код от них не зависит.
- **П11. `INT n`** — `vc_int(n);` (объявляется в `vc.h` на этапе B).
- **П12. Числа:** арифметика в `uint16_t`/`uint8_t` с явными приведениями;
  перенос и заём — через `uint32_t` (образец — `TxtNum`). `MUL/DIV/IDIV`: DX:AX
  как у 8086; деление на ноль и переполнение частного — `TRAP()` (VC на них не
  рассчитывает: **предположение**, при срабатывании — стоп, `DOUBTS.md`).
- **П13. `PUSHF/POPF`, `LAHF/SAHF`, `CLI/STI`** — честно через `r.flags`;
  `CLI/STI` меняют только бит IF.
- **П14. Сначала тест.** Единица считается переведённой, только когда её
  заголовок есть в `c/`; проверенной — когда харнесс прогнал её без
  расхождений (§4).
- **П15. Не переводить** `VCSETUP.ASM` и единицы, достижимые только из `EXEC`
  и выгрузки (`Exec*`, `LoadOvl*`, `New27`): их тело — `TRAP();` с
  комментарием `не переводится: EXEC (PLAN §0)`.
- **П16. Стоп-условия** (не обходить, а записать в `vc-wasm/DOUBTS.md`:
  установлено/не установлено/как узнать — и отдать патч с этой записью):
  исполнение байтов, записанных программой (самомодификация); чтение или
  подмена своего адреса возврата (`POP` адреса, данные после `CALL`);
  косвенный переход на адрес, которого нет в `units.json`; `IN/OUT`;
  арифметика над CS для кода; любое расхождение харнесса, причину которого не
  удалось установить за 3 шага сбора информации.

## 4. Этап B: харнесс «сверка по процедурам»

Идея: настоящий `VC.COM` работает в go2dos по сценарию клавиш. На входе в
переведённую единицу харнесс снимает состояние, дожидается возврата в
оригинале, потом прогоняет перевод (wasm) из того же состояния и сравнивает.

**Где.** `vc-wasm/lockstep/` — вложенный Go-модуль (R8):

```
module github.com/unxed/go2dos/vc-wasm/lockstep
require github.com/unxed/go2dos v0.0.0
replace github.com/unxed/go2dos => ../..
require github.com/tetratelabs/wazero <последняя>
```

**Сборка wasm для харнесса:** `LOCKSTEP=1 sh vc-wasm/c/build.sh` даёт
`-DVC_LOCKSTEP`. Тогда в `vc.h`:
- `vc_int(n)` и `vc_far(seg, off)` — импорты модуля `vc` (`int`, `far`);
- `vc_missing(addr)` — импорт: вызывается перед `TRAP()` в `vc_dispatch` и в
  заглушках, чтобы харнесс знал, кто не переведён;
- экспорт `vc_call(uint16_t addr)` — `vc_dispatch(addr)`.

**API go2dos** (**установлено** по коду, проверить на шаге B1):
`machine.New(machine.Config{Drives: map[byte]string{'C': dir}, Codepage: 437})`,
`m.Load(`C:\VC.COM`, "")`, `m.RunScript(ctx, steps, machine.ScriptOptions{})`
(образец — `e2e/vc_test.go`). `m.CPU` — `*cpu.CPU` с полями
`BreakAt map[uint32]bool` (ключ `CS<<16|IP`) и `Break func(*cpu.CPU)`;
`machine.New` ставит их сам только при непустом `Config.Break` — не передавай
его, ставь свои после `New`. Память — `m.Mem.Read8/Write8` (линейный адрес).

**Шаги этапа B:**

- **B1.** Проверить на `HexByt` (`A47D`), что `Break` срабатывает **до**
  исполнения команды по адресу, и что из колбэка можно читать регистры и
  память. Если нет — стоп (П16).
- **B2.** Режим покрытия: `BreakAt` на все входы единиц, счётчик попаданий;
  итог — `vc-wasm/data/coverage-<сценарий>.txt` (`адрес имя число`).
- **B3.** Режим сверки (алгоритм ниже). Отчёт — `data/verified.txt` (имена
  единиц, у которых не меньше 5 проверенных вызовов и ни одного расхождения;
  меньше 5 — если вызовов было меньше) и сводка в stdout.
- **B4.** Статистика `INT`: `(n, AH)` и число вызовов по сценарию →
  `data/int-usage-<сценарий>.txt` (нужна этапу D).

**Алгоритм сверки:**

1. Вход в единицу E (её адрес в `BreakAt`, CS = сегмент PSP VC — взять
   `m.CPU.S[cpu.CS].Sel` после `Load`): снять регистры и всю память (1 МиБ) —
   S0; запомнить SP0 и адрес возврата по `SS:SP0`. Кадры вложенных проверок
   держи стеком.
2. Пока кадр открыт, на каждую команду `INT` (адреса из `units.json`, ключ
   `BreakAt` и на адрес следующей команды) — снять регистры и память до и
   после и записать `{n, regs_in, regs_out, diff}`. Повторное срабатывание на
   том же `INT` до возврата (ожидание клавиши, `cpu.ErrRetry`) — тот же вызов.
3. Возврат: CS:IP равен адресу возврата и `SP > SP0` — снять S1.
4. Запуск перевода: память S0 в арену wasm (адрес — экспорт `vc_arena`),
   регистры — по `vc_regs` (раскладка `Regs` в `vc.h`), затем `vc_call(E)`.
   Импорт `vc.int` берёт следующую запись: сверяет `n` и регистры
   AX BX CX DX SI DI BP DS ES с `regs_in` (несовпадение — «разошлось до INT n»),
   применяет `regs_out` и `diff`. `vc.missing(addr)` — пометить кадр
   «заблокирован: <имя>» (это не ошибка).
5. Сравнение с S1: все регистры (включая SP, SS, DS, ES), флаги — только из
   `Флаги-выход:` единицы (харнесс читает их из заголовков `c/*.c`), память —
   вся, кроме `0000–04FF` (IVT и BDA: их меняют прерывания таймера) и
   1 КиБ под конечным SP в SS (мёртвая область стека).
6. Выборка: на единицу первые 10 вызовов и каждый 50-й, не больше 50 за
   прогон (флаги командной строки).
7. Отчёт об ошибке — одна строка: единица, номер вызова, первые 4 различия
   (`AX 1234!=1235`, `mem 0156:0A10 41!=42`).

Сценарии — скрипты клавиш в формате пакета `keys/` в
`vc-wasm/lockstep/scenarios/*.keys`, диск C: — временный каталог с
несколькими файлами (как в `e2e/vc_test.go`). **S1**: старт, ждать `10Quit`,
`Down` ×3, `Tab`, `Down`, `F10`, подтверждение выхода.

Готово, когда: харнесс на S1 подтверждает `HexByt`, `HexCod`, `TxtNum` (если
они вызываются в S1; если нет — добавить в S1 действие, которое их вызывает,
или проверить отдельным коротким сценарием), а намеренно испорченный перевод
(например, `+ 8` вместо `+ 7` в `HexCod`) даёт расхождение.

## 5. Этап C: перевод волнами

1. Множество цели — единицы из `coverage-S1.txt` (потом S2, S3 …, §8).
2. **Порядок — снизу вверх:** единица готова к переводу, если все её
   `callees` и `out_jumps` уже переведены (косвенные вызовы не учитываются:
   их ловит `vc_missing`). Среди готовых — сначала самые частые по покрытию.
   `tools/order.py` печатает следующую волну.
3. Волна: 10–25 единиц → перевод по §3 → `build.sh` (с `-Wall -Werror`) →
   харнесс → починка → `progress.py` → патч.
4. Проверенная единица не правится без причины, найденной харнессом.
5. Первые две волны: замерь, сколько строк asm переводится за сессию, и
   запиши в README («Трудоёмкость») — это первая оценка всего объёма.

## 6. Этап D: DOS-слой и терминал (боевая сборка)

Начинать, когда все единицы из `coverage-S1.txt` проверены.

- **Файлы:** `c/shim/start.c` (`_start`), `dos.c` (`INT 21h`), `bios.c`
  (`INT 10h/16h/1Ah`, прочие — «не установлено» по политике go2dos), `term.c`
  (рендер и клавиши), `wasi.h` (импорты `wasi_snapshot_preview1`: `fd_read`,
  `fd_write`, `fd_close`, `fd_seek`, `fd_readdir`, `path_open`,
  `path_filestat_get`, `path_unlink_file`, `path_rename`,
  `path_create_directory`, `path_remove_directory`, `clock_time_get`,
  `poll_oneoff`, `proc_exit`).
- **Образ:** `tools/gen_image.py VC.COM` → `c/build/image.c` (массив байтов,
  генерируется при сборке, не коммитится; `VC.COM` — из `listing.sh`).
- **Старт:** окружение в сегменте `0700h` (`COMSPEC=C:\COMMAND.COM`,
  `PATH=C:\`), PSP в `0800h` (поля PSP — как в `dos/dos.go`), образ в
  `0800:0100`, `CS=DS=ES=SS=0800h`, `SP=FFFEh` со словом 0 в стеке, вызов `Zero`.
  Распределитель памяти (`48h/49h/4Ah`) — MCB от конца блока VC до `A000h`.
  BDA: 80×25, режим 3. Экран — сегмент `B800h` в арене.
- **Какие функции DOS** — из `data/int-usage-S1.txt`; семантика — как в
  `dos/*.go` go2dos (переносить логику, не изобретать). Диск `C:` — preopen
  fd 3. Имена хоста, не влезающие в 8.3 или с символами вне кодовой страницы,
  в MVP **не показываются** (ограничение — в README; позже — алиасы как в
  `docs/NAMES.md`). Неподдержанная функция — сообщение в stderr и `proc_exit(70)`
  (fail fast).
- **Терминал:** кодовая страница 866 (таблица — из `cp/` go2dos); рендер —
  разница ячеек `B800:0000` с прошлым кадром в ANSI (SGR по атрибуту — как
  `machine.SGR`), вызывается при каждом обращении к клавиатуре. Клавиши —
  разбор ESC-последовательностей в скан-коды BIOS (таблица — из `keys/`).
  Опрос (`INT 16h AH=01h/11h`) при пустом буфере — `poll_oneoff` по fd 0 с
  таймаутом 50 мс. **Риск:** поддержка `poll_oneoff` на stdin в `wasmtime` не
  проверена — проверить первым шагом D (маленькая программа на C), иначе стоп.
- **Запуск:** `vc-wasm/run.sh` — `stty raw -echo`, `wasmtime run --dir=.
  vc.wasm` (текущий каталог — preopen fd 3, он же диск `C:`), `stty sane` в
  `trap`.

Готово, когда: `run.sh` показывает панели, стрелки двигают курсор, `F10`
выходит. Владелец проверяет в GNOME Terminal и far2l (инструкция — один блок
для вставки в терминал, AGENTS.md).

## 7. Этапы E и F

- **E. Сверка экранов целиком:** Go-тест во вложенном модуле: wazero с WASI
  запускает `vc.wasm` с теми же клавишами, что go2dos с `VC.COM`; на каждом
  `<waitfor>` текст экрана (арена `B800`) совпадает с `m.Screen()`.
- **F. Натив через w2c2** (`github.com/turbolent/w2c2`, собирается CMake;
  **установлено**: не принимает функции с несколькими результатами, требует
  заголовков libc — для freestanding нужны заглушки). Сначала Linux x86-64 с
  WASI-реализацией w2c2, потом Cortex-M4 (`clang --target=thumbv7em-none-eabi`)
  — только замер размера. Цифры — в README, рядом с таблицей ревью.
