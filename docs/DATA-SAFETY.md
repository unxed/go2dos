# Потеря данных при пробросе файловой системы хоста (T22)

Модель: каталог хоста становится диском DOS (`C:`, `-drive D=…`). Всё, что DOS-программа
(VC, `COMMAND.COM`, любая другая) может сделать с файлами этого каталога, она делает на самом
хосте, без возврата: удаление, перезапись, переименование. Этот документ — разбор того, что
может пойти не так, что уже проверено тестами и какие настройки есть. Источник проверок —
`dos/safety_test.go`, `machine/shell_test.go`.

## Настройки

| Флаг | Что делает | Умолчание |
|---|---|---|
| `-ro C,D` или `-ro all` | диски только для чтения: создание, запись, удаление, переименование, атрибуты и время отвечают «доступ запрещён» (программа видит ещё и критическую ошибку «Write protect» через INT 24h) | выключено |
| `-confine` | символические ссылки, ведущие за пределы каталога диска (и битые), не видны программам: через ссылку нельзя выйти из проброшенного каталога | выключено |
| `-host-exec` | команды хоста из DOS (`!команда`, `START`, `DOS-HOST/HOSTEXEC`); это выход из песочницы целиком, `-ro` и `-confine` на него не действуют | выключено |

Умолчания «выключено» оставляют прежнее поведение. Если нужна защита по умолчанию — вынести
в настройку и переключить умолчание (решение владельца, см. вопросы в конце).

## Разбор рисков

| № | Риск | Состояние |
|---|---|---|
| R1 | Выход за корень диска через `..`, `\..\..`, `C:..\x` | Не выходит (`TestDotDotStaysInRoot`: классические вызовы и `lfnResolve`). |
| R2 | Символическая ссылка внутри каталога ведёт наружу: программа читает и пишет чужие файлы, `cd` в каталог за пределами | Возможно по умолчанию (ссылки следуют как на хосте). Закрыто `-confine` (`TestConfineHidesEscapingLinks`). |
| R3 | Номер `~N` в 8.3-имени менялся при появлении других файлов: программа или панель VC, державшая `ДЛИННО~1.TXT`, действовала над другим файлом | **Исправлено**: номер закреплён за файлом на время работы и не переиспользуется (`TestShortNameStableWhenFilesAppear`). Между запусками go2dos номера считаются заново по порядку имён: имя `~N`, записанное в файл (батник, список), может указывать на другое. |
| R4 | Молчаливая перезапись и удаление: `COPY` на существующую цель, создание файла (`3Ch`) усекает, `DEL`/`41h` без возврата | Как в DOS. Смягчение: `-ro`. Не сделано: «корзина» (`-trash DIR`: удаление и перезапись переносят старый файл туда), подтверждение перезаписи. |
| R5 | `REN`/`56h` поверх существующего файла | Отказ, файл цел (`TestShellLongNames`, `rename` в `dos/files.go`). |
| R6 | Два файла с именами, различающимися только регистром (`a.txt`, `A.txt`) | Второй получает `~N`; обращение по имени без учёта регистра берёт первый по порядку имён. Данные не теряются, но можно открыть не тот. Не исправлено, записано. |
| R7 | Файлы на хосте меняются во время работы (другая программа, сам пользователь) | Кэш каталога сбрасывается после своих операций, чужие изменения видны после повторного чтения каталога; ошибка при устаревшей записи — отказ ОС, а не порча (номера `~N` стабильны, R3). Блокировок нет. |
| R8 | Псевдонимы для имён вне кодовой страницы (`NAMES.md`): создание «по псевдониму» даёт имя оригинала | Реестр на время работы; после перезапуска псевдоним неизвестен, пока каталог не прочитан. Перезаписи чужого файла нет (проверено в тестах имён). |
| R9 | Имена, зарезервированные ОС хоста (Windows: `CON`, `NUL`, `AUX`, завершающие точки и пробелы) | Не проверялось (проверка на Linux). Записано в `DOUBTS.md`. |
| R10 | Сбой: прерывание go2dos посреди записи | Запись идёт через ОС без `fsync` до закрытия; при `kill` без закрытия дескрипторов последние блоки сохраняются как у любого процесса, но не гарантированы. Журнала операций нет. |
| R11 | Хост-команды (`-host-exec`) | Любые действия пользователя хоста, без ограничений; по умолчанию выключено. |
| R12 | Режим `-lenient` | Не касается файлов; неподдерживаемые вызовы просто отвечают отказом. |

## Что дальше (не сделано)

1. **Корзина `-trash DIR`** (R4): вместо удаления и вместо перезаписи старый файл переносится в
   каталог с меткой времени. Нужны: место для корзины вне проброшенных каталогов, политика
   очистки, что делать с каталогами (переносить целиком), что с переименованием при совпадении
   имён.
2. **Журнал изменений `-fslog FILE`**: одна строка на каждую изменяющую операцию (кто, что, куда),
   чтобы можно было разобраться после ошибки; компактный (пара сотен байт на операцию).
3. **Умолчания.** Включить ли `-confine` по умолчанию; включить ли подтверждение перезаписи в
   встроенном `COPY` (сейчас молча, как DOS).
4. R6 и R9 — решить, нужны ли.
