# Гейты для правок ассемблерного кода (VC, позже HX)

Правка 16-битного ассемблера опасна тем, что ошибки тихие: испорченный
регистр или флаг ломает что-то далеко от места правки. Поэтому каждая правка
проходит гейты по порядку. Провал гейта — откат правки. Два провала подряд —
стоп: запись в `docs/DOUBTS.md` и передача задачи старшей модели
(`TASKS.md`).

## База для VC 4.05

`github.com/pts/pts-vc405-port` (BSD-2, как сам VC). В нём исходник VC 4.05
портирован на NASM, JWasm, WASM и mininasm, есть воспроизводимая сборка на
Linux (ассемблеры в комплекте) и эталоны в `golden/`. Без правок сборка
побайтно совпадает с оригиналом.

## Гейты

- **G1. Эталон.** Немодифицированный исходник собирается в эталонные байты
  (`golden/`). Если нет — окружение сломано, править нельзя.
- **G2. Два ассемблера.** Модифицированный исходник собирается NASM и JWasm в
  одинаковые байты. Расхождение означает ошибку синтаксиса одного из
  ассемблеров.
- **G3. Размер.** `.COM` не больше 65280 байт (0FF00h). У VC 4.05 файл —
  64990 байт, запас — 290 байт. Не влезает — стоп (T15c).
- **G4. Локальность.** Новый код — в новых процедурах. В существующем коде —
  только точки вызова (`CALL` в одном месте). Сравнение листингов до и после
  показывает изменения только в этих местах и сдвиг адресов, без других
  изменений байтов.
- **G5. Контракт.** У каждой новой процедуры в комментарии указано, какие
  регистры и флаги она портит; всё остальное сохраняется (`PUSH`/`POP`).
  Точка вызова проверена по исходнику: изменённые регистры там не нужны.
- **G6. Данные.** Раскладка существующих структур, формат `VC.INI` и таблицы
  клавиш не меняются, если карточка не требует этого явно.
- **G7. Поведение.** Весь e2e-набор go2dos зелёный, плюс новый e2e-тест на
  функцию (сценарий клавиш и проверка экрана). Если функция пользуется нашим
  API, тест есть и для случая, когда API нет: VC должен вести себя как раньше.
