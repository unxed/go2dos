# Гейты для правок ассемблерного кода (VC, позже HX)

Правка 16-битного ассемблера опасна тем, что ошибки тихие: испорченный
регистр или флаг ломает что-то далеко от места правки. Поэтому каждая правка
проходит гейты по порядку. Провал гейта — откат правки. Два провала подряд —
стоп: запись в `docs/DOUBTS.md` и передача задачи старшей модели
(`TASKS.md`).

## Что уже есть

`docs/VC-BUILD.md` и job `build-vc`: VC собирается JWasm. Для 4.99.09 `VC.COM`
совпадает с TASM побайтно, `VC.OVL` — нет; для 4.05 нужны патчи, и сборка
не побайтная. Поэтому для 4.05 база — pts-vc405-port (ниже).

**T15a:** `tools/build-vc405-pts.sh` собирает 4.05 `VC.COM` из pts-vc405-port (пин —
`PTS_COMMIT` в `third_party/vc/PINS`) и сверяет с эталоном TASM; `build-vc.sh` и CI
требуют совпадения. Это G1 для 4.05; проверен запуском в песочнице, в CI ещё не прогонялся (см. `DOUBTS.md`).

## База для VC 4.05

`github.com/pts/pts-vc405-port` (BSD-2, как сам VC). В нём исходник VC 4.05
портирован на NASM, JWasm, WASM и mininasm, есть воспроизводимая сборка на
Linux (ассемблеры в комплекте) и эталоны в `golden/`. Без правок сборка
побайтно совпадает с оригиналом.

## Гейты

- **G1. Эталон.** Немодифицированный исходник собирается в эталонные байты
  (`golden/`). Если нет — окружение сломано, править нельзя.
- **G2. Два ассемблера.** Модифицированный исходник собирается NASM и JWasm в
  одинаковые байты. Расхождение означает ошибку синтаксиса одного из
  ассемблеров.
- **G3. Размер.** `.COM` не больше 65280 байт (0FF00h). У VC 4.05 файл —
  64990 байт, запас — 290 байт. Не влезает — модуль расширений (ниже).
- **G4. Локальность.** Новый код — в новых процедурах. В существующем коде —
  только точки вызова (`CALL` в одном месте). Сравнение листингов до и после
  показывает изменения только в этих местах и сдвиг адресов, без других
  изменений байтов.
- **G5. Контракт.** У каждой новой процедуры в комментарии указано, какие
  регистры и флаги она портит; всё остальное сохраняется (`PUSH`/`POP`).
  Точка вызова проверена по исходнику: изменённые регистры там не нужны.
- **G6. Данные.** Раскладка существующих структур, формат `VC.INI` и таблицы
  клавиш не меняются, если карточка не требует этого явно.
- **G7. Поведение.** Весь e2e-набор go2dos зелёный, плюс новый e2e-тест на
  функцию (сценарий клавиш и проверка экрана). Если функция пользуется нашим
  API, тест есть и для случая, когда API нет: VC должен вести себя как раньше.
- **G8. Необязательность.** Без `VCEXT.BIN` (если он используется) VC
  работает как раньше: весь e2e-набор зелёный.

## Если не влезает: модуль расширений (VC 4.05)

Крупные функции не помещаются в 290 байт, поэтому они живут вне `VC.COM`.

- **`VCEXT.BIN`** — плоский бинарник NASM (`org 0`) рядом с `VC.COM`.
  - Заголовок: подпись `VCX1`, слово — число точек входа, затем слова —
    смещения точек входа.
  - Исходник — `third_party/vc/ext/`, сборка — в CI вместе с VC.
- **В `VC.COM` — только крючки** (они проходят G3 и G4):
  - загрузчик при старте: выделить память `INT 21h/48h`, прочитать
    `VCEXT.BIN` из каталога VC (путь — из окружения, как VC ищет свой
    `VC.INI`), проверить подпись, запомнить сегмент;
  - точки вызова: `CALL` маленькой заглушки, которая делает far call в
    модуль или ничего не делает, если модуля нет (G8).
- **Контракт каждой точки входа** — в комментарии модуля: входные и выходные
  регистры, что портится (G5). Модуль не обращается к данным VC иначе, как
  через переданные в регистрах указатели.
- **Сначала исследовать** (`VCMEM.INC`): как VC 4.05 управляет памятью вокруг
  `EXEC` и подкачки — чтобы блок модуля не был освобождён или перезаписан.
  Неясно — стоп.
  **Разведка сделана** (чтением): точка загрузчика — `Init11`, подробности и оценки —
  `DOUBTS.md`, «Модуль расширений VC 4.05: разведка памяти».

## Новые настройки

Раскладку `VC.INI` не трогаем (G6). Настройки новых функций хранятся в
`VCEXT.INI` и читаются модулем.

## VC 4.99.09: оверлей

У 4.99.09 основной код лежит в `VC.OVL` (EXE), ограничения `.COM` на него не
действуют, поэтому функции добавляются в `VCOVL.ASM` с теми же гейтами.
- **G1 для 4.99.09:** сначала добиться побайтной пересборки `VC.COM` и
  `VC.OVL` из исходников `ddanila/vc`. Для `VC.COM` есть JWasm в
  `third_party/jwasm` ветки `build`; про `VC.OVL` сведения в этой ветке
  расходятся — проверить.
- Без побайтной пересборки правки 4.99.09 не начинать: стоп, запись в
  `DOUBTS.md`.
