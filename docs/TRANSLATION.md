# Трансляция x86 → wasm: решение, архитектура, план

Статус: архитектура и план, кода нет. Пункты **исследовать** — проверить до
реализации и записать результат в `docs/DOUBTS.md`. Ссылки вида §N ведут в
`docs/DESIGN.md`.

## Идея и решение

Идея: раз исходники VC на ассемблере, пусть JWasm «собирает в wasm», и VC
работает как wasm-модуль, без интерпретатора, со скоростью нативного кода.

Для бинарников статическую трансляцию (путь B2 в §11) мы отложили из-за трёх
проблем: код и данные перемешаны, есть оверлеи, есть косвенные переходы. Из
исходников ассемблер знает, где код, где данные и где метки, поэтому первая
проблема снимается, а третья становится решаемой.

**Решение:**

1. **Бэкенд wasm в JWasm не пишем.** Это сопровождение форка C-кода с
   семантикой MASM ради одного выходного формата. JWasm собирает программу как
   обычно, а от него берутся только **метаданные**: адреса инструкций, метки,
   границы кода и данных (листинг `-Fl`; что именно доступно при выводе `-bin`
   — **исследовать**).
2. **Транслятор один** — на Go, в go2dos: переводит x86 в wasm. Им же
   пользуется JIT B1. Разница между AOT и JIT только в том, откуда берётся
   список блоков для трансляции.
3. **Смешанное исполнение с откатом на интерпретатор.** Транслированный блок
   работает над тем же `cpu.State` и той же памятью, что и интерпретатор. Всё,
   что не покрыто, исполняет интерпретатор: незнакомый адрес, изменённый код
   (по счётчикам записей страниц, §5), перемещённый код (оверлей VC 4.99.09).
   Поэтому трансляция никогда не обязана быть полной, чтобы быть верной.
4. **Список блоков — общий интерфейс, у него три источника:**
   - метаданные ассемблера, когда есть исходник: VC через JWasm, HX, DN через
     ассемблерный вывод компилятора Pascal;
   - покрытие из прогонов интерпретатора: сценарии клавиш записывают
     исполненные адреса. Это работает для любого бинарника, включая NC, без
     дизассемблирования;
   - JIT в рантайме: блок транслируется при первом исполнении (B1).

## Как это меняет картину go2dos

go2dos становится двухуровневым.

- **Интерпретатор** — универсальный исполнитель и эталон.
- **Трансляция** — ускорение и способ поставки.

Между ними **платформенный ABI**: HLE (BIOS, DOS, наши API: буфер обмена,
UTF-8 имена, мост WASI). Транслированный модуль вызывает его через импорты
wasm точно так же, как интерпретатор через ловушки. Отсюда следствие:
сопровождаемая программа (VC, позже HX, DN) может поставляться как
`VC.wasm` плюс хост с HLE. Под go2dos хост — Go и wazero, позже в браузере —
та же HLE в go2dos, собранном под wasm (M12).

## Архитектура

- **Блок** — wasm-функция `b(state) → next`: исполняет инструкции от входного
  линейного адреса до перехода, возвращает следующий адрес или код выхода
  («нужен интерпретатор», «ловушка HLE», «прерывание»).
- **Состояние** — `cpu.State` и память 1 МиБ + HMA в линейной памяти
  wasm-модуля. Go-сторона работает с той же памятью (через представление
  памяти wazero — **исследовать**, разделяется ли буфер без копирования).
- **Диспетчер** на Go: таблица «линейный адрес → блок»; перед входом
  проверяется, что счётчики записей страниц блока не изменились с момента
  трансляции (AOT — после загрузки проверяется хэш байтов блока). Иначе
  исполняет интерпретатор до следующего известного входа.
- **Прерывания и IRQ** проверяются на границах блоков; `INT n` и ловушки HLE
  завершают блок.
- **Флаги** — вычисляются только там, где их читают: анализ живости внутри
  блока, на выходе из блока — полное значение.

## План

Шаги мелкие, у каждого свой тест, порядок важен.

- **T0. Исследование:**
  - API wazero для импортов и общей памяти;
  - метаданные JWasm (`-Fl`, раскрытие макросов, `-bin`);
  - есть ли в VC 4.05 запись в собственный код (поиск по исходникам);
  - ассемблерный вывод Free Pascal для i8086 (для DN);
  - размер и время компиляции модулей в wazero.
- **T1. Ядро транслятора:** инструкция → wasm для того же набора команд, что
  у интерпретатора. Тест — **те же SingleStepTests**: каждый тест проходит
  через транслированный однокомандный блок и сравнивается с ожиданием.
- **T2. Смешанное исполнение:** диспетчер, откат на интерпретатор, проверка
  счётчиков страниц. Тест — e2e VC 4.05 даёт те же экраны; дифференциальный
  режим «шаг транслятора против шага интерпретатора» с остановкой на первом
  расхождении состояния.
- **T3. JIT (B1):** трансляция блоков при первом исполнении — работает для
  любой программы, включая NC.
- **T4. AOT:** список блоков из метаданных JWasm (VC 4.05, затем 4.99.09) и из
  записанного покрытия; модуль транслируется заранее и проверяется хэшами при
  загрузке.
- **T5. Поставка:** `VC.wasm` + хост HLE как единый артефакт; позже — в
  браузере вместе с M12.

## Чего не делать

- Не добавлять бэкенд wasm в JWasm.
- Не требовать полноты трансляции: непокрытое исполняет интерпретатор.
- Не делать отдельный путь трансляции для AOT и для JIT.
