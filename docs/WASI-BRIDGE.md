# Мост DOS → WASI: архитектура, решение и план

Статус: архитектура и план. Кода нет. Пункты с пометкой **исследовать** —
проверить до реализации и записать результат в `docs/DOUBTS.md`. Ссылки на
разделы вида §N ведут в `docs/DESIGN.md`.
Результаты исследования R1–R5 — [WASI-RESEARCH.md](WASI-RESEARCH.md); в
нём же поправка: witx лежит в ветке `wasi-0.1`, каталог `preview1/witx`, а не
`legacy/preview1`.

## Идея

DOS-программа получает доступ к хосту через API песочницы WebAssembly — WASI.
Там уже есть всё нужное: файлы с UTF-8 путями, 64-битные смещения, каталоги,
часы, случайные числа, аргументы и окружение. Поддержка WASI есть почти везде:
wasmtime, wazero, Wasmer, Node, браузерные прослойки. Значит, DOS-программа,
написанная под мост, сможет работать с любой современной системой тем же
способом, что и wasm-модуль.

## Решение

1. **Берём WASI preview1** (`wasi_snapshot_preview1`). Это плоский ABI из целых
   чисел, дескрипторов и указателей на память, и он ложится на 16-битный
   реальный режим. WASI 0.2 (preview2) построен на Component Model с
   каноническим ABI — для DOS это слишком тяжело, отложено.
2. **Оба API остаются.** UTF-8 имена (§19, `UTF8NAMES.md`) — быстрый путь для
   программ, которые уже работают через LFN: VC, DN, патч NC. Клиенту нужно
   только включить режим и поправить вывод имён на экран. Кроме того, этот API
   реализуем и на реальном DOS (через DOSLFN), где хоста нет. Мост WASI — для
   новых и портируемых программ (C, Pascal), которым нужен весь хост, а не
   только имена. Перевести VC на мост — значит переписать весь его файловый
   слой, а это противоречит принципу «без глобальных переписываний».
3. **Порядок.** Исследование R1–R5 можно делать когда угодно. Реализация идёт
   этапом M11, после UTF-8 имён (M10): к этому моменту готовы AMIS-диспетчер и
   общие пути к дискам, мост переиспользует оба. Следом — M12, go2dos под
   wasm-рантаймом и в браузере: там мост становится прямым пробросом WASI.

## Архитектура

```
 DOS-программа ── far call (AX = функция, DS:SI = параметры) ──┐
                                                               ▼
 go2dos: hle-заглушка «trap; RETF» ─► пакет wasidos (семантика preview1)
                                       │  preopen-каталоги = диски DOS
                                       ▼
                       Go os / time / crypto/rand
                       ├─ нативная сборка: ОС хоста
                       └─ сборка GOOS=wasip1: настоящий WASI хоста
```

- **Обнаружение** — AMIS (`INT 2Dh`), как у UTF-8 имён (один диспетчер AMIS на
  оба API). Подпись: производитель `DOS-WASI`, продукт `PREVIEW1`. Вход —
  функция AMIS 01h «get private entry point»: она возвращает DX:BX, по этому
  адресу программа делает far call. Это быстрее, чем `INT`.
- **Вызов:** AX — номер функции по таблице из спеки моста (своя фиксированная
  нумерация, не порядок в witx). DS:SI — блок параметров: параметры в порядке
  witx, i32, указатели и дескрипторы — по 4 байта, i64 — 8 байт, без
  выравнивания. На выходе AX — errno WASI (0 — успех), CF=1, если AX≠0.
  Выходные значения, как и в preview1, пишутся по указателям.
- **Указатели** — 32-битные far-указатели в раскладке x86 (младшее слово —
  смещение, старшее — сегмент), совместимые с `LDS/LES`. Поэтому структуры
  preview1 (`iovec`, `filestat`, `dirent`, `prestat`, `event`,
  `subscription`) сохраняют раскладку wasm32 байт в байт: у wasm32 указатель
  тоже 4 байта. Хост переводит far-указатель в линейный адрес и читает буфер
  линейно.
- **Строки и пути** — UTF-8 (`ptr`, `len`), разделитель `/`, пути
  относительно preopen-дескриптора.
- **Preopen** — fd 3, 4, … по одному на каждый подключённый диск, имя `C:`,
  `D:`, …. Песочница та же, что у DOS-дисков, и разрешение путей общее с
  пакетом `dos`.
- **Дескрипторы** принадлежат процессу (PSP) и закрываются при его
  завершении. Таблица fd отдельна от DOS-хэндлов, смешивать их нельзя.
  fd 0–2 — консоль: вывод переводится из UTF-8 в экранную кодовую страницу,
  ввод идёт с клавиатуры.
- **`args_*` / `environ_*`** — из хвоста PSP и окружения процесса,
  перекодированные из OEM в UTF-8. **`proc_exit`** работает как `4Ch`.
  **`sched_yield`** и ожидание в `poll_oneoff` — через простой (§7).

## План работ

Шаги мелкие, и каждый проверяется тестом. Порядок важен.

**W0. Исследование** (результаты — в `DOUBTS.md`):

- **R1.** Список функций preview1 и раскладки структур — по
  `wasi_snapshot_preview1.witx` в репозитории `WebAssembly/WASI` (каталог
  legacy/preview1). Зафиксировать подмножество v0.
- **R2.** Можно ли переиспользовать WASI-реализацию wazero
  (`imports/wasi_snapshot_preview1`) с памятью, которая не является памятью
  wasm. Если нельзя без внутренних API — реализовать поверх Go `os`
  (ожидаемый вариант).
- **R3.** Ограничения Go `GOOS=wasip1`, на котором в M12 будет работать сам
  go2dos: доступные preopens, сокеты.
- **R4.** Детали AMIS 3.6: проверка наличия, функция 01h, обязательные функции
  AMIS. Общее с `UTF8NAMES.md`.
- **R5.** Компиляторы для клиентов: gcc-ia16 (TK Chia), Open Watcom 2.0,
  Free Pascal (цель i8086-msdos). Где их взять для CI и как запускать.

**W1. Спека** `docs/DOSWASI.md` на английском (для других реализаций):
обнаружение, вызов, таблица функций v0, раскладки, коды ошибок.

**W2. Каркас:** общий AMIS-диспетчер `INT 2Dh` (если его ещё не сделал M10),
пакет `wasidos`, заглушка входа «trap; RETF».
Тест — `.COM`, который находит мост и получает точку входа.

**W3. v0 без файлов:** `args_sizes_get/args_get`, `environ_sizes_get/
environ_get`, `fd_write` на fd 1/2, `clock_time_get`, `random_get`,
`proc_exit`. Тест: `.COM` пишет через `fd_write` UTF-8 строку `Привет 世界`;
при CP866 на экране `Привет ??`.

**W4. Файлы:** `fd_prestat_get`, `fd_prestat_dir_name`, `path_open`,
`fd_read`, `fd_write`, `fd_seek`, `fd_tell`, `fd_close`, `fd_filestat_get`,
`path_filestat_get`, `fd_readdir`, `path_create_directory`,
`path_remove_directory`, `path_unlink_file`, `path_rename`. Тест: создать,
прочитать и перечислить файл `файл 世界.txt`, проверить байты имени на хосте.

**W5.** `poll_oneoff` (только подписки на часы), `sched_yield`, чтение fd 0.

**W6. Клиентский набор** `clients/wasidos/`: макросы nasm и заголовок C
(Open Watcom и gcc-ia16) с far-указателями, пример программы, бинарники в
`testdata` (как `testdata/progs`).

**W7. Дальше:** сокеты (в preview1 есть только `sock_accept/recv/send/
shutdown` на preopen-сокетах — **исследовать**, достаточно ли этого);
прослойка RTL для Free Pascal, чтобы DN мог работать через мост (§20).

## Чего не делать

- Не заменять UTF-8 имена мостом и не переводить на мост VC.
- Не тянуть Component Model / WASI 0.2 в DOS-ABI.
- Не смешивать fd моста и DOS-хэндлы.
