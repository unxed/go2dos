## Договорённости (ответ владельца «окей» на рекомендации)

- **`-confine`** — по умолчанию выключен (ссылки на хосте — рабочий приём; модель угроз — свои
  программы над своими файлами; `-host-exec` всё равно выходит из песочницы).
- **`-fslog`** — не делать, пока нет реального случая (точка подключения — `fsys.wp()`, она уже
  стоит во всех местах изменения файлов).
- **Перезапись через `3Ch`** — не трогать (корзина утонула бы во временных файлах; VC сам
  спрашивает подтверждение; для рискованных сеансов есть `-ro`).
- **T15f (утечка блока VCEXT, 4 КБ на запуск)** — пока оставить. Следующий шаг — разведка, почему
  `VC.COM` ломается при росте образа на 16 байт при запасе 22 (см. ниже), и только потом выбор
  между «код в `VCEXT.BIN` + адрес блока в PSP» и «блок внутри вторичного сегмента». Сборку без
  малого режима не делать.
- **WASI-мост** — не начинать без указания владельца (архитектурный блок; план в `WASI-BRIDGE.md`).
- Два решения принял исполнитель до появления правила об согласовании; владелец явно не
  возражал, но и не подтверждал по отдельности — при желании пересмотреть: подмена имён в снимке
  экрана (`-real-names`, `dos/namedisplay.go`) и плоская корзина с журналом и суффиксом `.~N`
  (`dos/fstrash.go`).

## Как работать с кодом

- Проверка: `go vet ./... && go test ./...`; e2e с VC — `sh tools/build-vc.sh`, затем
  `GO2DOS_VC_DIR=$PWD/.cache/vc-build/bin go test ./e2e` (около 90 с).
- Проверять патч на **чистом клоне** репозитория (`git am`), а не в рабочей копии.
- Номера патчей в отдельном каталоге; `git format-patch` даёт числовые суффиксы — брать печатаемое имя.
- README при наложении патчей конфликтовал (у владельца он отличается около «## Запуск»):
  правки README отдавать отдельно, от его версии файла.
- Патч VC `third_party/vc/patches/vc-4.05-clip.patch`: файл `vc.asm` со смешанными концами строк
  (CRLF/LF). Править в байтах (`\r\n`), не через текстовый режим Python; порядок: применить текущий
  патч к `vc.asm` из `pts-vc405-port`, внести правку, `git diff --no-index a/vc.asm b/vc.asm`,
  исправить заголовок на `a/vc.asm b/vc.asm`. `git apply` внутри игнорируемого каталога требует
  `GIT_CEILING_DIRECTORIES`. `.gitattributes` помечает патчи VC бинарными.
- Устройство VC 4.05 (важно для T15f): резидентная часть — от `Start` до `Init00`; всё от `Init00` до
  `LastPtr` («малый режим», `LoadFl`=1 по умолчанию) VC освобождает перед запуском программы и
  перечитывает с диска загрузчиком `VVV` (`Alloc0`, контрольная сумма). Поэтому переменные в этой
  части (в том числе `ExtSeg`) после запуска программы снова нулевые; PSP и резидентная часть
  переживают перезагрузку. `Release` относится к списку резидентных программ (F65), а не к каждому
  запуску.
- Диагностика: `GO2DOS_EXEC_TRACE=N`, `-trace FILE -trace-filter int21`, `dos.MemBlocks()` для цепочки
  памяти, `sessionOptsHook` в `e2e/vc_test.go` — свой драйвер клавиатуры в e2e-тесте.
