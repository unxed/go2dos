# Сборка Volkov Commander свободными средствами

Статус: первый шаг M9 (DESIGN §18) сделан — воспроизводимая сборка без наших
правок VC. Каркас: `third_party/vc/`, `tools/build-vc.sh`, `tools/vc-diff.py`,
job `build-vc` в CI. Пометки: **установлено** (исходник, лог CI, запуск) и
**предположение** (проверки нет). Все запуски — в GitHub Actions, не локально.

## Итог

- VC 4.99.09: `VC.COM` собирается JWasm **побайтно как TASM**; `VC.OVL`
  собирается (`-mz`), но не побайтно, и в работе не проверен.
- VC 4.05: JWasm «как есть» её не собирает; с патчем исходников (54 строки в
  8 файлах) и двумя правками самого JWasm собирается, `VC.COM` проходит наш
  e2e-тест (`TestVC405PanelsAndQuit`), но не побайтно как TASM.
- Проприетарное ПО (TASM) не нужно. JWasm собирается из исходников на
  `ubuntu-latest` за ~15 с.

## Как собирают в ddanila/vc

Источник: `build.sh`, `.github/workflows/build.yml`, `third_party/jwasm/README.md`
на коммите `7331dbb` (`https://github.com/ddanila/vc/blob/7331dbb8e536692ec09147eb363d3d9b65478ec1/build.sh`).

- **Установлено.** Основной путь — TASM 4.1 (`TASMX /z/m9/kh10000`) и TLINK 7.1
  из подмодуля `zajo/TASM`, исполняются в MS-DOS 4.0 под QEMU (образ дискеты
  `ddanila/msdos` 0.1, диск FAT16 из mtools). 4.05: `TLINK /t/x` (COM).
  4.99.09: `VC.COM` — `TLINK /t`, оверлей `VC.OVL` — `TLINK` (EXE, переименован).
- **Установлено.** Дополнительно, нативно: `jwasm -q -Zg -Zne -DOFFICIAL -bin
  VC.ASM` — только `VC.COM` 4.99.09. Для 4.05 JWasm-сборки в ddanila/vc нет.
- **Установлено.** Для JWasm в `versions/4.99.09` ветки `build` сделаны правки
  (блоки `IFDEF __JWASM__`, `OPTION oldstructs`, `.DOSSEG`, явные размеры
  `LABEL BYTE`, `WORD PTR` у непосредственных операндов, чтобы форма `CMP AX,imm`
  совпала с TASM). Версия 4.05 в `build` и `master` идентична и не правилась.
- **Установлено.** В `zajo/TASM` нет файла лицензии (GitHub API: `license: null`),
  описание: двоичные файлы «из официального дистрибутива». **Предположение:**
  это коммерческое ПО Borland, распространять и использовать его в нашем CI
  нельзя. Мы его не используем.

## Свободные ассемблеры: что проверено

- **JWasm** (Sybase Open Watcom Public License) — собирает всё, см. ниже.
  Коммит `a7c6e70`: нужен для `VCOVL.ASM` (константное деление, `89fc1ee4f`,
  новее релиза 2.21pre1; по README ddanila/vc).
- **NASM** — **установлено:** исходники в синтаксисе MASM/TASM (`STRUC`, `UNION`,
  `.MODEL`, `PROC ... USES`, `LOCAL`, `EQU`-строки); синтаксис NASM
  несовместим, перенос — глобальное переписывание, которое мы исключили.
- **UASM, Open Watcom WASM** — не проверялись: **предположение** — UASM
  (форк JWasm) даёт те же ограничения, WASM слабее JWasm; JWasm достаточно.

## VC 4.99.09

- **Установлено** (CI, прогон `exp-vc` и `build-vc`): `VC.COM`, собранный
  JWasm, имеет SHA-256 `85fcbb96…d7661`, равный TASM-сборке релиза; так и без
  нашего патча JWasm, и с ним (патч не ломает идентичность).
- **Установлено:** `VC.OVL` — `jwasm -mz` (формат `-bin` для него невозможен:
  ошибка A2198 «Invalid fixup type for BIN» на межсегментных адресах).
  Сравнение с TASM/TLINK:

  | | JWasm | TASM/TLINK |
  |---|---|---|
  | размер файла | 117624 | 117824 |
  | заголовок MZ | 6000 байт | 6144 байта |
  | образ после заголовка | 111624 | 111680 |
  | перемещений | 1491 | 1491 |
  | SS:SP | 1B41:0900 | 1B44:0900 |
  | min alloc (параграфов) | 145 | 144 |

  Число и начало таблицы перемещений совпадают; различается раскладка
  сегментов (образ длиннее на 56 байт у TLINK). Дизассемблирование образов
  даёт ~470 блоков различий (частично шум: данные, сдвинутые на другие байты).
- **Предположение:** различия — выравнивание заголовка (TLINK кратно 512) и
  сегментов; функциональных различий нет. **Не проверено:** 4.99.09 пока не
  доходит до панелей в go2dos (DOUBTS: «VC 4.99.09 не доходит до панелей»), так
  что работоспособность `VC.OVL` из JWasm проверить нечем. В `PINS` и в
  сравнении `build-vc.sh` он помечен «не побайтно, ожидаемо».

## VC 4.05: что мешает JWasm и что сделано

Прогон «JWasm без правок» (`-Zne -Zg -bin`) — множество ошибок; первые:
`A2209 Syntax error: JUMPS`, `A2141 Statement not allowed inside structure
definition`, `A2229 Structure improperly initialized`, `A2183 Use of register
assumed to ERROR` (30+). Часть ошибок — следствия других, поэтому правки
вводились по шагам, каждый прогон — в CI. Итог (`patches/vc-4.05-jwasm.patch`):

| Что в исходнике (TASM) | Ошибка JWasm | Правка |
|---|---|---|
| `JUMPS` | A2209 | `OPTION OLDSTRUCTS,NOSCOPED`; Jcc JWasm расширяет сам |
| метки внутри `PROC` видны всюду | A2102 «Symbol not defined» (JWasm по умолчанию как MASM 6: метки в `PROC` локальны) | `NOSCOPED` |
| имена полей `STRUC` глобальны (`ComnIni.LoadSiz`, `[BX].LastMnu`) | A2271 | `OLDSTRUCTS` |
| `Имя LABEL BYTE` внутри `STRUC` (`TreList`, `StarClk`, `EdHelp`, `HlpPrms`, `HlpInfo`) | A2141 | поле нулевой длины `Имя DB 0 DUP(?)` |
| то же в `BOXMN`, которая инициализируется `<…>` (`mSelTot`) | A2152: нулевое поле потребляет значение | убрано из структуры, `mSelTot = mCtrl + 0` после `ENDS` |
| переменные структур `EPB EPBs ?`, `STAR n DUP(?)` | A2229 | `<>` |
| `PROC C NEAR` и `USES …` отдельной строкой | A2209, A2092 | `PROC NEAR C USES DS SI …` |
| `LOCAL ClkBuf :WORD:6` | A2039 | `ClkBuf[6] :WORD` |
| `VcVers EQU '4.05'` в списке `DB` | A2076 | `EQU <'4.05'>` (**предположение:** строка ≤4 символов трактуется как число) |
| `JMP CS:[BX+SI]` | A2182 | `JMP WORD PTR CS:[BX+SI]` |
| `LOOP` вне диапазона | A2053 | TASM при `JUMPS` расширяет и `LOOP` (**установлено** по дизассемблированию эталона: `E2 02 / EB 03 / E9 rel`); записано явно, один случай (`F39_52`) |
| код и метки в `.DATA`/`.CONST` (Tiny, всё в `DGROUP`) | A2183 | правка JWasm (ниже) |

Правки JWasm (`patches/jwasm-tasm-compat.patch`, на коммит `a7c6e70`):

1. **Установлено** (`src/simsegm.c`, 306:
   `https://github.com/Baron-von-Riedesel/JWasm/blob/a7c6e70a63cf364b05e44decafc338b4915a8bb0/src/simsegm.c#L306`):
   `.DATA`/`.CONST` выдают `ASSUME CS:ERROR`, и метка кода в них — ошибка A2183.
   В модели Tiny теперь `ASSUME CS:DGROUP`, как делает `.CODE`.
2. **Установлено** (`src/H/instruct.h`, макрос `ari`): для `ADD/OR/ADC/SBB/AND/SUB/
   XOR/CMP AX,imm` JWasm выбирает форму `83 /n ib` (первая в таблице), TASM —
   «аккумулятор» `05/0D/…/3D iw`; длина одинакова, но байты разные. Строка
   `A,I` перенесена в таблице на первое место. Без этого в 4.05 было около 90
   отличающихся инструкций, у 4.99.09 это решено правкой исходников (`WORD PTR`).

## Чем 4.05 отличается от TASM-сборки

Прогон `build-vc` (CI):

- `VC.COM`: 64976 байт против 64990; `VCSETUP.COM`: 56173 против 23615.
- **Установлено** по `tools/vc-diff.py` (сопоставление по мнемоникам):
  1. `LEA BX,Var` — TASM делает `MOV BX,OFFSET Var` (на 1 байт короче), JWasm —
     `LEA` (минимум 2 места);
  2. рамка `LOCAL` в `Input0`: `ADD SP,-26` против `SUB SP,30` (**предположение** о причине:
     TASM отводит слово каждой байтовой локальной переменной, JWasm — байт);
  3. 4 условных перехода на границе дальности (`737F`): JWasm оставляет
     короткими, TASM расширил до `Jcc +3 / JMP near`.
- **Предположение:** остальные ~300 блоков — шум дизассемблирования данных и
  сдвиги от пунктов 1–3; полного соответствия «блок — причина» нет.
- `VCSETUP.COM`: **предположение** — JWasm пишет в файл хвост неинициализированных
  данных (`?`) нулями, TLINK его отбрасывает; на работу не влияет, но файл
  больше. Не обрезается, чтобы не угадывать границу.
- **Функционально:** `TestVC405PanelsAndQuit` на собранном `VC.COM` проходит
  (панели, переход в каталог, выход) — как на эталонном. Это единственный
  автоматический тест; до побайтного совпадения и до более широких тестов
  равенство функций — **предположение**, подкреплённое тестом.

## Что нужно для правок

Реальных правок VC (буфер обмена WinOldAp, LFN для 4.05, UTF-8 имена) не
делалось. Для них:

1. **Решить, где живёт код.** DESIGN §18 говорит о копии в `third_party/vc`.
   Предлагается при первой же функциональной правке завести там дерево
   `4.05/` (исходники ddanila/vc с применённым `vc-4.05-jwasm.patch`, `LICENSE`
   рядом, лицензия BSD-2 это допускает) и собирать из него; закреплённый
   коммит оставить как «опорную точку» для сверки с upstream. Пока правки — не
   патчи поверх патчей. Правки JWasm остаются патчем к закреплённому коммиту.
2. **Стенд go2dos.** WinOldAp — `INT 2Fh/17xx` в `hle` (DESIGN §9, поток A) и
   тест в `e2e/` со скриптом клавиш; без обработчика в эмуляторе новый код VC
   проверить нечем. LFN для 4.05 — `INT 21h/71xx` в `dos` (AGENTS, п. 2);
   эталон кода LFN — `versions/4.99.09/VCCOMMON.INC`.
3. **Точки вставки** (**предположение**, по именам файлов, не по разбору):
   выделение и вставка текста — `VCEDIT.INC` (редактор), `VCVIEW.INC`
   (просмотр); командная строка — `VC.ASM`/`VCSUB*.INC`. Нужен разбор кода
   перед правкой.
4. **Побайтная идентичность 4.05** — желательна как защита от регрессий
   инструмента; закрывается тремя пунктами выше (LEA, рамка LOCAL, границы
   переходов) и сверкой остатка. Но после первых функциональных правок она
   теряет смысл, поэтому стоит ли тратить усилия — решение владельца.
5. **4.99.09:** `VC.OVL` из JWasm проверить после закрытия расследования в
   DOUBTS (StartMain).
6. **Windows/macOS:** `tools/build-vc.sh` проверен только на Ubuntu. JWasm на
   macOS собирается с заглушкой `malloc.h` (см. `third_party/jwasm/README.md`
   в ddanila/vc); если понадобится — отдельный шаг.
7. **Upstream:** правку 4.05 под JWasm можно предложить в `ddanila/vc`
   (там уже есть такая для 4.99.09).
