# Что нужно Norton Commander от BIOS, DOS и железа, и готовность go2dos

Статус: исследование, 2026-10-01. Поток B. Код не менялся; все ссылки на код —
по состоянию ветки `main` на коммит `99a01fd` (после него в `main` изменились
только документы).

Пометки в документе (как в `DOUBTS.md`):

- **[У]** — установлено: есть читаемый источник (URL и/или цитата) или прочитан
  код репозитория.
- **[П]** — предположение: правдоподобно, но источника нет. Проверяется трассой
  на копии NC у владельца (§9), до проверки по нему ничего не чинится.

## 0. Краткий итог

1. **Установленных сведений о том, какие именно прерывания и порты использует
   NC, в открытых источниках нет.** Исходников NC нет; ни дизассемблирования,
   ни списка вызовов, ни трасс из эмуляторов найти не удалось (§1). Поэтому
   настоящий список требований получится только трассой самого NC. Из этого
   следует первая задача для потока A: режим, в котором go2dos не
   останавливается на первой неподдерживаемой функции, а пишет её в трассу и
   отвечает «функция не поддерживается» (§8, п. 1).
2. Установлено про NC (§3): состав дистрибутива (`NC.EXE` — маленький
   перезагрузчик, `NCMAIN.EXE` — основная программа, `NCEDIT.EXE` и просмотрщики —
   отдельные EXE), запуск программ через **новый `COMMAND.COM`** с последующим
   самоперезапуском NC, работа с мышью, режим «EGA Lines» (43/50 строк), `Ctrl-O`
   как «спрятать панели», экран «DOS memory blocks», файлы `NC.INI`, `NC.EXT`,
   `NC.MNU`, `treeinfo.ncd`.
3. **Готовность go2dos к NC.** Есть: загрузка EXE, EXEC и возврат в родителя,
   файловый слой, текстовый экран в `B800`, клавиатура через порт 60h/IRQ1,
   таймер, минимальный INT 2Fh. Нет или заглушено: `COMMAND.COM`, мышь
   (INT 33h и ввод во фронтенде), режимы 43/50 строк, критические ошибки
   INT 24h и Ctrl-Break, IOCTL `440Dh`, XMS/EMS, `INT 13h/25h/26h` (§5).
4. **Самый опасный пункт, не связанный с интерфейсами:** ядро CPU намеренно
   ведёт себя как 8086 (`PUSH SP`, биты 12–15 FLAGS, `cpu/state.go`). Любая
   проверка «процессор не ниже 286» в программе скажет «8086». Что NC так
   проверяет — [П]; один из форумных источников утверждает, что NC 5.5x
   требует 286 (§3, §5, п. A3).
5. **Свободных NC нет.** Ни одна версия Norton Commander не распространяется
   свободно; найденные источники называют его «Commercial proprietary
   software» (§7). Для CI годятся клоны: Volkov Commander (BSD-2, уже есть),
   Dos Navigator 1.51 (исходники открыты, лицензия — BSD-подобная с рекламным
   пунктом; есть оговорка о Turbo Vision), Directory Freedom (GPL,
   ассемблер, поддерживает 43/50 строк), HFM (GPL, Pascal), DC (freeware, без
   исходников) (§6).

## 1. Метод и границы

Что читалось: Википедия (en, ru), сайт Softpanorama
(раздел «The History of Development of Norton Commander», с листингами
дистрибутивов 1.0, 2.0, 3.0, 4.0, 5.x и пресс-релизом Symantec на 4.0),
документация NC 3.0 на `gladir.com`, форумы (VOGONS, WinWorld), описания на
`archive.org`, дамп каталога RBIL (`ctyme.com/intr`), исходники DN 1.51
(`github.com/maximmasiutin/Dos-Navigator`), исходники VC (`github.com/ddanila/vc`)
и код go2dos.

Что НЕ делалось: NC не скачивался ни в репозиторий, ни куда-либо ещё, его
файлы не дизассемблировались. По нашим правилам (AGENTS.md, «гадать
запрещено») всё, что можно узнать только из бинарника NC, помечено [П] и
передано на трассу (§9).

Ограничение источников: поисковые запросы по «NC + INT 21h/2Fh/EMS/XMS/NCMAIN
disassembly» ничего содержательного не дали; точного описания NC на уровне
прерываний публично не найдено. Это отрицательный результат, а не свидетельство
того, что NC этих прерываний не использует.

Требования к процессору/памяти, которые удалось найти:

- NC 4.0: DOS 3.1+, 512 КБ, XT/AT/PS/2 [У, пресс-релиз Symantec в [1]].
- NC 3.0: `NC.EXE` (перезагрузчик) занимает 13 КБ ОЗУ [У, gladir [2]:

- NC 5.5x: комментатор на WinWorld: «8088? This needs at least 286» и «I'd guess

- NC 5.0 работает в DOSBox 0.74 [У, описание на archive.org [8]:
  «Tested in DOSBox 0.74 and Windows 7»] — то есть для запуска достаточно
  того, что даёт DOSBox (оговорка: это не говорит, какие именно функции
  используются).

## 4. Что известно о «классе» программы по DN и VC

Т. к. у NC источников нет, ориентиром служат клоны, у которых они есть. Это
**установлено только для DN/VC**; для NC — [П].

Dos Navigator 1.51 (исходники `maximmasiutin/Dos-Navigator` читались во
временной копии вне репозитория и в него не переносились), что он делает на уровне интерфейсов:

- Определение среды: `INT 21h/30h` (версия ≥20 — считает OS/2), `INT 21h/2B01h`
  c `CX='DE', DX='SQ'` (DESQview), `INT 2Fh/160Ah` (Windows). `DN.PAS`, `CheckOS`.
- Отдача кванта: `INT 28h`, `INT 15h/1000h` (DESQview), `INT 2Fh/1680h`.
- Буфер обмена: `INT 2Fh/1700h–1709h`, формат `CF_OEMTEXT` (7). `WINCLP.PAS`.
  Это **закрывает вопрос из `DOUBTS.md`** «CF_TEXT или CF_OEMTEXT»: этот клиент
  использует CF_OEMTEXT.
- EMS: открытие устройства `EMMXXXX0` (`3Dh`), `IOCTL 4407h`, `INT 21h/3567h`,
  `INT 67h/40h`, `42h`, … (`EXTRAMEM.PAS`, `OBJECTS.PAS`); XMS: `INT 2Fh/4300h`,
  `4310h`, `INT 15h`. Оверлеи Borland Pascal (`DN.OVR`, `OVERLAYS.PAS`,
  `OvrInitEMS`).
- Клавиатура: свой обработчик `INT 09h` с `IN AL,60h`, прямое чтение кольца
  в `0040:001A..`, цепочка к прежнему обработчику через `PUSHF/CALL`; свои
  `INT 1Bh`, `INT 21h`, `INT 23h`, `INT 24h` (`SYSINT.ASM`).
- Видео: `INT 10h` (курсор `03h`, позиция, `00h`, …), прямая запись в `B800`.
- Диски: `INT 13h` (форматирование, `FMTUNIT.PAS`), `INT 17h` (печать, `PRINTMAN.PAS`).
- Запуск команд: обмен с загрузчиком через `INT 2Fh/9902h–9904h`
  (`RUNCMD.INC`; резидентный загрузчик собирается из `DN.ASM` — [П]), а не
  `COMMAND.COM /C`.
- Центральная проверка процессора: `GETCPU.ASM` определяет 8088/8086/V20/V30/
  186/286/386/486 по поведению команд (классический способ — `PUSH SP` и
  биты 12–15 FLAGS) и затем читает `SMSW`, `SGDT`, `SIDT`.
- Сборка: Borland Pascal 7.0, TASM, TLINK, `BPC.CFG` с `{$G+}` (286-код).

VC 4.05/4.99.09: зафиксировано в `DOUBTS.md`/`DESIGN.md` (DESQview-проверка,
запрос 3DAh, EXEC оверлея, `INT 2Fh/168Fh,150Bh,4300h`, `INT 10h/FEh`).

Вывод для NC: типичный набор тот же (определение среды, квант, мышь, клавиатура
через BIOS/порт 60h, прямой `B800`, EXEC, оверлеи, возможно EMS/XMS), но
конкретику даст только трасса.

### 6.1. Dos Navigator: юридический статус, исходники, компилятор

Установлено:

- Исходники DN 1.51 опубликованы RIT Research Labs; на GitHub: единственный
  коммит `b268678` «Dos Navigator v1.51 by RIT Research Labs… released on April
  19, 1999», ~150 файлов `*.PAS`, `*.ASM`, `BUILD.BAT`, `BUILDDN.BAT`, `BPC.CFG`.
  GitHub API: `license: null`, лицензия — в `README.TXT` и в заголовках файлов.
- Текст лицензии (`README.TXT`): «This product is free for commercial and
  non-commercial use as long as the following conditions are aheared to.
  Copyright remains RIT Research Labs… » плюс три пункта: сохранять
  уведомление в исходниках, воспроизводить его в документации бинарников и
  **«All advertising materials mentioning features or use of this software
  must display the following acknowledgement: "Based on Dos Navigator by RIT
  Research Labs."»**. Википедия пишет «3-clause BSD license»; по тексту это
  BSD **с рекламным пунктом** (3-й пункт — рекламный).
- Оговорка Википедии (en.wikipedia.org/wiki/DOS_Navigator): исходники DN
  содержат код Turbo Vision от Borland без ясных прав на производные работы;
  в DN OSP — изменённый runtime Virtual Pascal с неясным статусом. В
  `maximmasiutin/Dos-Navigator` Turbo Vision представлен собственными копиями
  (`OBJECTS.PAS`, `DRIVERS.PAS`, `VIEWS.PAS`, `MENUS.PAS`, …) под лицензией RIT.
  Права RIT на эти файлы не больше прав на Turbo Vision у самого RIT — [П],
  юридическое заключение не запрашивалось.
- Бинарник DN 1.51: распространяется на сайте RIT (`ritlabs.com/en/products/dn/`
  по README; в момент проверки сайт отдавал страницу защиты от ботов) и в
  Internet Archive (`archive.org/details/DOSNavigator_1020`; какая это версия —
  не проверено). Что именно можно положить в CI — [П]; по тексту лицензии бинарник
  свободен при выполнении условий, но источник бинарника должен быть
  проверяем по SHA-256.
- Компилятор: **Borland Pascal 7.0, TASM, TLINK** (`README.TXT`, `BUILDDN.BAT`:
  `bpc dn /dDN /GP /Q /B`, затем PKLITE). Borland Pascal 7.0 — коммерческий
  продукт, свободно скачать его для CI нельзя [П: наши источники не показали
  свободной раздачи BP 7.0]. Варианты по `DESIGN.md` §20: Free Pascal
  (цель i8086-msdos) — [П]: DN использует оверлеи, `asm`-вставки TASM, большие
  модели и т. п., сборка не проверялась; Virtual Pascal — 32-битный, для
  DN OSP (`unxed/dn2l`, Linux), DOS-режим не поддерживает.
- Ветка проекта владельца `unxed/dn2l` — порт DN OSP на Linux («Modified BSD with
  an exception prohibiting re-licensing… including GPL»), собирается Virtual
  Pascal; к запуску в go2dos отношения не имеет.

Вывод: для CI достаточно **готового бинарника DN 1.51** (если найдётся
проверяемый источник), собирать его не нужно. Сборка из исходников — отдельная
задача (§20 `DESIGN.md`).

## 8. Список недостающего по приоритету

Приоритет вычислен от цели «NC 5.0/5.51 в панелях → команды и запуск программ →
остальное». Пункты помечены [У]/[П] по тому, подтверждена ли необходимость
источником.

### P0. Чтобы вообще доехать до панелей (и узнать остальное)

1. **Режим «собери всё»** (`-lenient`): `hle.Unsupported` не останавливает машину,
   а пишет в трассу и возвращает «функция не поддерживается» (CF=1, AX=1 для
   INT 21h; регистры без изменений для остальных). Плюс сводка в конце:
   «какие INT/AX вызывались, сколько раз, какие из них не реализованы».
   Один прогон NC даст настоящий список. Поток A: `hle/`, флаг — поток B (`cmd/`).
2. **Выбор модели CPU** (`Config.CPU`: 8086 / 80186 / 80286): ведёт к
   проверке «286+» [П: NC, WinWorld]. Для 286 в реальном режиме: биты 12–15
   FLAGS = 0, `PUSH SP` кладёт старое значение, `SMSW`, `LMSW` и т. п. — fail
   fast на защищённый режим.
3. **Метка тома** (`4Eh` с атрибутом 08h) и **определение дисков/типов**
   (`4408h/4409h/440Dh/32h/1Ch/36h`) [П: нужны панели и меню дисков]. Вернуть
   данные из конфигурации дисков (метка — имя каталога или `-label`).
4. **Режим INT 24h/1Bh/23h**: вызвать критический обработчик на ошибках
   (диск не готов, запись на защищённый диск), доставить `INT 1Bh` на
   Ctrl-Break и `INT 23h` на Ctrl-C [П; DN так делает].

### P1. Командная строка и запуск программ

5. **`COMMAND.COM`**: FreeCOM (GPL) как отдельная программа внутри эмулятора;
   `COMSPEC` на реальный файл; проверка `/C`, `/K`, возврат кода, `INT 2Eh`
   (B6, B7) [У: F2 для NC 3.0].
6. **Перезагрузка NC после программы** (F1, F2): проверить, что цепочка
   `NC.EXE → NCMAIN.EXE → COMMAND.COM → программа → возврат` работает: `4B00h`,
   `31h` и `27h`, `4Dh`, файлы `NC.INI`/`NCTMP.TMP`, `treeinfo.ncd` в корне диска.
   Тест — на VC/DN-подобных «запускалках» плюс трасса NC.

### P2. Ctrl-O, мышь, экран 43/50

7. **Мышь**: INT 33h (минимум: `0000h`, `0001h`, `0002h`, `0003h`, `0004h`,
   `0007h`, `0008h`, `000Bh`, `000Ch`) + события мыши во фронтенде (xterm
   mouse reporting) [У: F4].
8. **Экран 43/50 строк**: `INT 10h/1112h` (шрифт 8x8), `1202h/1201h`, BDA
   `0040:0084`, `Snapshot` и фронтенд на произвольное число строк; `bdaRows`
   ≠ 24; `INT 10h/1130h` отдаёт реальную высоту [У: F6 наличие; П: набор вызовов].
9. **`Ctrl-O`** (F5): проверить сохранение/восстановление пользовательского
   экрана (видеопамять — обычная RAM, это уже работает) и мигающий/яркий режим
   атрибута (`1003h`, порт `3C0h`) [П].

### P3. Остальное

10. **EMS/XMS**: пока ответ «не установлено» допустим; реализовывать только
    если трасса покажет, что NC без них не работает (F9, WinOldAp-подход
    «трасса сначала») [П].
11. **FCB-функции `0Fh–28h`, `1Bh`, `1Ch`, `1Fh`, `32h`**, `5Ch`, `5Dh`, `5Eh`, `3Dh`
    с режимами SHARE, `INT 2Fh/1000h` — по трассе [П].
12. **`INT 13h/25h/26h`** — для `NCDD`/`NCLABEL`/форматирования; вне целей PoC [У: наличие утилит; П: нужны ли для запуска].
13. **LFN `71xx`** (5.51 использует через Windows API; без Windows — не
    показывает, F11): M7, низкий приоритет для NC.
14. **Графические режимы** (просмотр графики, заставки): вне целей PoC.

### Топ-10 для потока A (по порядку работ)

1. `-lenient` режим и сводка вызовов (п. 1).
2. Модель CPU 286 (п. 2).
3. `INT 21h/440Dh`, исправление `4408h/4409h`, метка тома, `32h/1Ch` (п. 3).
4. Критические ошибки `INT 24h` и Ctrl-Break (`INT 1Bh/23h`) (п. 4).
5. `COMMAND.COM` (FreeCOM) и `INT 2Eh` (п. 5).
6. `INT 33h` — реальная мышь (п. 7).
7. Режим 43/50 строк: `INT 10h/11xx`, `bdaRows` (п. 8).
8. `INT 10h/1003h` и порт `3C0h` (мигание/яркие фоны) (п. 9).
9. EMS/XMS — только по трассе (п. 10).
10. `INT 13h`, `25h/26h`, `17h`, `14h` — заглушки с «устройство не готово»
    вместо fail fast, чтобы NC не падал на проверке принтера/дисков.

### Мост WASI и UTF-8 имена

После `08b3573` в `main` есть `docs/WASI-BRIDGE.md` и `DESIGN.md` §21: мост DOS →
WASI — отдельный путь для новых и портируемых программ. Для NC он не нужен:
NC работает через обычные `INT 21h`; UTF-8 имена (`UTF8NAMES.md`) — быстрый
путь для LFN-программ (VC, DN, патч NC), и они не зависят от того, что
требуется NC «из коробки». Поэтому требования этого документа никак не
зависят от моста и от M11/M12.

## 9. План проверки у владельца копии (как превратить [П] в [У])

### Методология тестирования на основе S2 (real-mode, нет extenders)

Тестирование NC проводится на стенде **S2** — конфигурация real-mode без
расширений памяти (XMS/EMS). Это позволяет:

1. **Изолировать ядро функциональности NC** от зависимостей расширений памяти
   и перемешиваний адресных пространств.
2. **Сфокусировать тестирование на INT 21h, INT 10h, INT 16h, INT 2Fh, INT 33h**
   без помех от DPMI, защищённого режима, лоадеров.
3. **Проверить совместимость с основными версиями** (NC 3.0–5.51) в одной
   конфигурации.

Стенд S2 включает:
- go2dos в real-mode (8086 или 80286, смотря версию NC).
- Отсутствие EMS/XMS-менеджеров (INT 2Fh/4300h отвечает «не установлено»).
- 640 КБ конвенциональной памяти (A000h по default).
- Стандартный BIOS (INT 10h текстовые режимы 0–3,7; INT 16h клавиатура;
  INT 08h таймер).
- Отключены: расширенные видеорежимы (40h+), INT 33h мышь (если не требуется
  конкретным тестом).

Переход на S2 позволяет быстро **отделить ошибки в ядре NC от ошибок в
обработке памяти**. Следующие версии стендов:
- **S2-noXMS** (текущее): 640 КБ, no EMS/XMS.
- **S2-286**: CPU = 80286, проверка PUSH SP и флаги 12–15.
- **S2-mouse**: INT 33h активна; события мыши от фронтенда.

### Процедура проверки

1. Вставить в `docs/NC-TESTING.md` шаблон запуска (там уже есть) и снять трассу
   с `-trace-filter int21,int10,int16,int2f,int33`.
2. Для каждого пункта матрицы с пометкой [П] в отчёте указать, был ли вызов; по
   результатам обновить этот документ (заменить [П] на [У] со ссылкой на трассу).
3. Сверить поведение NC в DOSBox-X с включённым журналом вызовов (в DOSBox-X
   есть режим отладки с журналированием INT; конкретные ключи — [П], проверить
   по документации DOSBox-X) — это независимый эталон.
4. Если у владельца нет NC, достаточно трассы любой из версий: 3.0, 4.0, 5.0,
   5.51 (таблица в `docs/NC-TESTING.md`).
