# Экран: окно любого размера, консоль хоста, длинные строки

Статус: архитектура и план (этап M10b), кода нет. Пункты **исследовать** —
проверить до реализации и записать результат в `docs/DOUBTS.md`. Ссылки вида
§N ведут в `docs/DESIGN.md`.

## Цели

1. Программы рисуются в окне любого размера, а не только 80×25/43/50.
   Для наших сборок (VC, DN, NC с патчем, Far под HX) это включено по
   умолчанию; для остальных — по флагу.
2. Режим консольного приложения: текстовый режим DOS отдаётся в консоль
   хоста, и VC запускается прямо в bash, как mc или far2l.
3. Длинные строки: если вывод команды перенёсся на следующую строку, хост
   получает склеенную строку.

## Решение

Ключ в том, чтобы разделить **два канала вывода**, которые в DOS и так
разные:

- **поток** — всё, что идёт через DOS/BIOS-телетайп: `INT 21h` (функции
  02h/09h/40h на CON), `INT 29h`, `INT 10h/0Eh`. Это вывод команд;
- **сетка** — прямые записи в видеопамять. Это полноэкранный интерфейс:
  панели, меню, диалоги.

Отсюда три режима отображения, выбираемых автоматически:

| Режим | Когда | Что делает |
|---|---|---|
| **pipe** | stdin/stdout хоста — не терминал | DOS-хэндлы 0/1/2 связаны с потоками хоста (OEM ↔ UTF-8); экрана нет. DOS-утилиты работают в конвейерах bash |
| **console** | терминал, по умолчанию | поток идёт в обычный буфер терминала (прокрутка, выделение, копирование — средствами терминала); сетка рисуется в альтернативном экране, только пока активен полноэкранный интерфейс |
| **grid** | флаг `-display grid` | всё рисуется сеткой, как сейчас |

В режиме console пользовательский экран VC под панелями (`Ctrl-O`) — это и
есть настоящий буфер терминала с историей команд. Длинные строки решаются
сами собой: поток не переносится на нашей стороне, перенос делает терминал
хоста, а копирует он склеенную строку.

**Когда включается сетка.**
- Наша сборка сама объявляет роль экрана через API (ниже): «полноэкранный»
  при показе панелей, «консоль» — при их скрытии и запуске команды.
- Программа, не знающая API, переводит экран в сетку первой прямой записью в
  видеопамять, и сетка держится до конца этого процесса. Это правило, а не
  эвристика по содержимому.

**Размер окна.**
- Эмулятор задаёт текстовый режим произвольного размера через те источники,
  из которых программы его и так читают: BDA `0040:004A` (колонки),
  `0040:0084` (строки − 1), `0040:004C` (размер страницы), `INT 10h/0Fh`,
  `INT 10h/1130h` (DL), регистры CRTC.
- Видеоокно расширяется до 64 КиБ (`B8000–C7FFF`), это 32768 ячеек.
  Окно хоста больше этого обрезается, а лишнее место остаётся пустым.
- Для программы, не знающей API, размер задаётся при старте: по умолчанию
  80×25, флаг `-size WxH|auto`. Для нашей сборки — размер окна хоста, и он
  следит за изменениями.

**Длинные строки в сетке (для §8).** Телетайп отмечает строку как
продолженную, когда переносит на правом краю. Отметки едут вместе со
строками при прокрутке и сбрасываются при перезаписи строки. `Screen.Text()`
склеивает продолженные строки — так же, как это делают эмуляторы терминала.

## API для наших сборок

Обнаружение через AMIS (`INT 2Dh`), общий диспетчер с UTF-8 именами и мостом
WASI; подпись: производитель `DOS-HOST`, продукт `TEXTWIN`. Черновик функций:

- **AL=10h — размер окна:** CX — колонки, DX — строки, BX — максимум ячеек.
- **AL=11h — следить за размером окна:** BL=1 вкл, 0 выкл. Если включено,
  при изменении окна эмулятор обновляет BDA и CRTC и кладёт в буфер
  клавиатуры зарезервированное слово-событие «размер изменился» (значение
  выбрать в S0). Программа обрабатывает его тем же кодом, что и смену числа
  строк 25/43/50: TUI-цикл и так ждёт клавиатуру, а этот путь в
  двухпанельниках уже есть.
- **AL=12h — роль экрана:** BL=0 консоль (поток), BL=1 полноэкранный
  интерфейс.

Английская спека — отдельным документом в S5, по образцу `UTF8NAMES.md`.
Win32-программы под HX получают то же через эмуляцию консоли HX: размер
буфера, событие `WINDOW_BUFFER_SIZE_EVENT` (§20, п. 3).

## План

Шаги мелкие, у каждого свой тест.

- **S0. Исследование:**
  - как VC 4.05/4.99.09 узнаёт число колонок и строк, параметрическая ли
    раскладка панелей или 80 зашито;
  - каким путём VC меняет режим 25/43/50 (его и использовать для события
    размера);
  - как ведут себя NC и DN при колонках ≠ 80;
  - как получать изменение размера: `SIGWINCH` / опрос `term.GetSize`,
    события консоли Windows;
  - значение слова-события.
- **S1. pipe:** хэндлы 0/1/2 ↔ потоки хоста. Тест: `go2dos hello.com | cat`
  и чтение stdin тестовой программой.
- **S2. Размер при старте:** `-size`, BDA/CRTC, видеоокно 64 КиБ. Тест:
  `.COM` рисует рамку по краям по данным BDA; VC без изменений при 80×50 и
  132×43 (результат зависит от S0).
- **S3. Отметки переноса и склейка в `Screen.Text()`.** Тесты на прокрутку и
  перезапись.
- **S4. console:** поток в обычный буфер, альтернативный экран при прямой
  записи в видеопамять или по роли, переходы без мерцания. Тест в pty
  (как smoke-тест фронтенда).
- **S5. API `DOS-HOST/TEXTWIN`** и английская спека.
- **S6. Клиенты:** сборка VC (размеры из BDA, событие размера, роли
  экрана), затем DN, NC с патчем, консоль HX.
