# Dos Navigator: исследование D1 (версия, исходники, лицензия, сборка, инструменты)

Статус: результаты этапа D1 из `docs/DN-PLAN.md`. Дата сбора: 2026-10-01.
Пометки: **установлено** — проверено по первоисточнику (с указанием, каким),
**предположение** — вывод без проверки.

Соблюдено правило `DN-PLAN.md`: исходники DN и Turbo Vision в репозиторий и в
этот документ не копировались (даже фрагментами). Они скачивались в
каталог вне репозитория только для чтения; ниже — пути, счётчики, хэши и
выводы. Свои проверки по исходникам DN можно повторить командами из
раздела «Как повторить».

## 1. Какая версия DN и где исходники

**Установлено.** Последняя версия RIT Research Labs — **DN 1.51**, выпущена
19 апреля 1999 г. (дата и авторы — в сообщении единственного коммита
репозитория `maximmasiutin/Dos-Navigator`; Wikipedia, «DOS Navigator»:
«1.50 — последняя shareware-версия», 1.51 — стабильная; «in late 1999 Ritlabs
decided to make version 1.51 … completely free with freely available source
code»).

Где лежат исходники DN 1.51:

Вывод. **Установлено:** исходники 1.51 в версии RIT доступны на двух
независимых хостингах (сайт ritlabs и GitHub) в одинаковом виде. Для скриптов
D2 лучше брать официальный URL ritlabs плюс проверку SHA-256 выше (в духе
`tools/fetch-vc.sh`); GitHub — запасной. Каталоги `EXE`/`OUT` скрипт
создаёт сам.

Состав архива (**установлено** подсчётом): 99 866 строк Pascal в 122 файлах
`.PAS`; 10 файлов `.ASM` (3 478 строк); 51 файл `.PAS` содержит встроенный
`asm` (428 блоков); каталог `RESOURCE` (`ENGLISH`, `RUSSIAN` — исходники
языковых файлов и диалогов, собираются утилитой `RCP.PAS`); `BUILD.BAT`,
`BUILDDN.BAT`, `BPC.CFG`. Названия модулей совпадают с TV: `OBJECTS`, `DRIVERS`,
`VIEWS`, `MENUS`, `DIALOGS`, `HISTLIST`, `MEMORY`, `VALIDATE`, `COLORSEL`,
`STRINGS`, `TVHC` и т.д.; в дереве есть и собственные расширения (`DNAPP`,
`MICROED`, `FLPANEL`, …). Обратите внимание: из списка модулей в DN-PLAN в 1.51 нет
файлов `Outline`, `StdDlg`, `MsgBox`, `Editors`, `TextView`, `App`
(**установлено** по списку файлов); есть собственные `DNAPP`, `DNSTDDLG`,
`MICROED`, `MESSAGES`, вероятно, занявшие их место (**предположение**). Список
модулей для аудита D3 надо составлять по этому дереву, а не по дистрибутиву BP7.

## 2. Что сказано о лицензии в самих исходниках

**Установлено** (читалось `README.TXT` и заголовки файлов 1.51):

- `README.TXT`: «Dos Navigator 1.51, Copyright (c) 1991-99 RIT Research Labs.
  All rights reserved.», продукт бесплатен для коммерческого и некоммерческого
  использования при соблюдении условий. Условия — BSD-подобные: сохранять
  уведомления об авторских правах; (1) исходники при распространении — с
  уведомлением, перечнем условий и отказом от гарантий; (2) бинарники — с тем
  же в документации; (3) **рекламные материалы, упоминающие продукт или его
  использование, должны содержать фразу «Based on Dos Navigator by RIT
  Research Labs»** (то есть это четырёхпунктная лицензия с рекламным
  условием, а не «BSD-3-Clause», как пишет Wikipedia); есть и требование
  указывать RIT Research Labs как автора использованных частей.
- Тот же текст стоит в заголовке каждого просмотренного `.PAS`
  (`OBJECTS`, `VIEWS`, `DRIVERS`, `MENUS`, `DIALOGS`, `DNAPP`, `MEMORY`,
  `HISTLIST`, `VALIDATE`, `COLORSEL`).
- **Пять файлов прямо сохраняют уведомление Borland:** `OBJECTS.PAS`,
  `MEMORY.PAS`, `HISTLIST.PAS`, `STRINGS.PAS`, `VALIDATE.PAS` (строка 51:
  «Copyright (c) 1990 by Borland International»; в `OBJECTS.PAS` — «This module
  is based on Turbo Vision Objects Unit»). В остальных файлах TV-происхождения
  (`VIEWS`, `DRIVERS`, `MENUS`, `DIALOGS`, `COLORSEL`) упоминаний Borland нет,
  хотя модули называются так же, как в TV. Это не доказывает отсутствие
  заимствований — для этого и нужен аудит D3.
- В исходниках нет отдельного файла лицензии Borland и нет утверждения, что
  Borland разрешила распространение производного кода.

**Установлено по сторонним источникам:**

- Wikipedia: «the code included an implementation of the Turbo Vision library
  based on the version from the Turbo Pascal distribution, and the latter was
  never released under a license that allows creation of derivative works».
- README dn2l (запись от 28-10-2020, автор — владелец проекта): часть файлов,
  опубликованных RIT, основана на исходниках Turbo Vision для Turbo Pascal,
  «never published by Borland under any permissive license»; перечислены
  `collect.pas` (в 1.51 такого файла нет, есть `OBJECTS.PAS`; соответствие —
  **предположение**: README dn2l говорит о переименовании `collect.pas` в
  `objects.pas`), `colorsel.pas`,
  `dialogs.pas`, `drivers.pas`, `histlist.pas`, `memory.pas`, `menus.pas`,
  `tvhc.pas`, `validate.pas`, `views.pas`; под подозрением — `dnapp.pas`,
  `microed.pas`, `messages.pas`, `dnstddlg.pas`. Этот список — отправная точка
  аудита D3 (**предположение**, пока не подтверждён детекторами).
- DN OSP и dn2l добавляют своё: в OSP попали модифицированные части RTL
  Virtual Pascal (лицензия VP запрещает распространять изменённую версию), поэтому
  dn2l заменил их патчами (README dn2l).

**Вывод (предположение, не юридическое заключение):** условия RIT на их
собственный код — разрешающие, но с рекламным пунктом, несовместимым с GPL
(так считает FSF для четырёхпунктной BSD; здесь нужно сверить с первоисточником
FSF); на TV-часть RIT дать права не могла, если Borland их не давала, — и
вопрос статуса остаётся на владельце проекта и юристе, как и сказано в
`DN-PLAN.md`.

## 3. Чем собирается

**Установлено** (`README.TXT`, `BUILD.BAT`, `BUILDDN.BAT`, `BPC.CFG`):

- Родная сборка 1.51 — **Borland Pascal 7.0** (`bpc dn /dDN /GP /Q /B`; в
  `BPC.CFG` — `/$O+` (оверлеи), `/$G+` (286), `/$N+` (сопроцессор)) плюс **TASM и
  TLINK** для `.ASM`; в `BUILDDN.BAT` после сборки — упаковка `pklite`, рядом
  с `dn.exe` кладётся `dn.ovr` (в `DN.PAS` — `uses Overlay, Overlays`).
  **Предположение:** ключа целевого режима (`/CP`) в командной строке нет, значит
  цель — реальный режим DOS (по умолчанию для `bpc`; `/GP` — карта публичных
  имён, не защищённый режим).
- Три `.ASM` написаны в режиме Ideal TASM (`LZWC2`, `UUE2INC`, `_MHZ`); остальные
  — в MASM-подобном синтаксисе (`.model tiny`/`Small`): перенос на JWasm/NASM
  возможен лишь по файлам, **предположение**, не проверялось.
- Внешние модули (по `uses`): `Dos`, `Overlay` из RTL Borland Pascal; в условных
  ветках для OS/2 и Windows — `os2def`, `winprocs`, `wintypes` и т.п.; в
  части кода — модули Async Professional TurboPower (`ApPort`, `ApUart`,
  `ApFossil`, `OOCom`, `OOZModem` …) — это сторонний код, в архиве его нет
  (**установлено** разбором `uses` вне комментариев; в 1.51 они для DOS-сборки
  с терминалом/модемом, и без них эти части не соберутся).
- BP7 — несвободный компилятор; открытого легального источника, откуда CI мог
  бы его скачать, не найдено (**предположение**: не искалось исчерпывающе;
  владельцу придётся указать свою копию — в духе NC-TESTING, «скрипт на машине
  пользователя»). Единственный путь без BP7 — другие компиляторы ниже.

**Free Pascal, цель i8086-msdos** (`wiki.freepascal.org/DOS`, страница помечена
как частично устаревшая; `sourceforge.net/projects/freepascal/files/msdos/3.2.2/`):

- **Установлено:** кросс-компилятор выпускается: в 3.2.2 есть
  `fpc-3.2.2.i386-linux.cross.i8086-msdos.tar.xz`,
  `fpc-3.2.2.x86_64-linux.cross.i8086-msdos.tar.xz` и Windows-вариант. Модели
  памяти: tiny, small, medium, compact, large, huge (`-WmLarge` — «the memory
  model used by Turbo Pascal version 4 and above»); wiki: «It can compile Turbo
  Pascal 7 code with less changes needed, compared to GO32V2 (no need to port
  the inline assembly code)». Для сборки нужны NASM (стартовый код RTL) и
  внутренний ассемблер/компоновщик (в 3.0.x — Open Watcom `wlink`/`wlib`).
- **Установлено:** ограничения: структуры данных не больше 64 КБ; модуль не
  больше 64 КБ кода (обход — `{$HUGECODE on}`); поддерживается только
  вызов `pascal`.
- **Установлено** (листинг `rtl/msdos` в `gitlab.com/freepascal.org/fpc/source`:
  `system.pp`, `dos.pp`, `sysutils.pp`, `classes.pp`, `msmouse.pp`, `ports.pp`,
  `prt0*.asm`): модуля `Overlay`/`Ovr` для i8086-msdos в RTL нет, слов
  «overlay» на странице wiki «DOS» нет. **Предположение:** оверлеи BP7 в FPC
  не поддерживаются; DN 1.51 при этом использует `Overlay`, значит, при
  переносе нужна модель памяти medium/large с `{$HUGECODE on}` и без
  оверлеев — влезет ли в 640 КБ, неизвестно, проверять сборкой в CI.
- **Со слов README dn2l** (автор сам ставит «AFAIK»; не проверялось): при
  сборке DN во FPC нужен ключ `-Sd`, в файлах с ассемблером — `{$asmMode intel}`,
  а `inline`-функции с телом до `implementation` FPC не принимает. Для i8086 встроенный
  ассемблер FPC — **предположение**, что его синтаксис покрывает 428 блоков DN;
  не проверялось.
- **Не проверено вообще:** собирается ли DN целиком хотя бы одним FPC. Ветка
  `fp_experiments` репозитория `unxed/dn2l` — попытка с заменой TV на Free
  Vision; по записи от 22-05-2025 в README dn2l автор считает перенос на
  Unicode-FV сопоставимым по трудности с созданием DN заново (`dn3l`).

**Virtual Pascal.** **Установлено** (README dn2l):
DN OSP (32-битный, многоплатформенный) привязан к Virtual Pascal (freeware,
не поддерживается), dn2l собирается им через IDE и конвертер `pe2elf`;
дистрибутив VP берётся с `old-dos.ru` и распространяется вместе с dn2l в
неизменном виде по лицензии VP. По README dn2l, VP нужен для 32-битной
ветки DN OSP (в dn2l — Linux через `pe2elf`). **Предположение** (по памяти, не
проверено по источнику): VP не создаёт 16-битный код реального режима DOS, так
что для go2dos (8086) он бесполезен, а путь VP относится к DN OSP, а не к DN 1.51.

**NDN** (Necromancer's DN): по README dn2l, в отладочном файле `ndn.dbg`
встречаются строка «Free Pascal 3.2.0 2020/10/18», `VPSYSLOW.PP` и `COLLECT.PAS`
— то есть сборка FPC поверх RTL Virtual Pascal и собственная TV-ветка DN;
исходники NDN закрыты (**установлено** по тому же README; самих файлов `.dbg` не
изучали).

## 4. Free Vision

- **Что это.** Установлено (`wiki.freepascal.org/Free_Vision`; FPC FAQ
  «Free Pascal — Porting Turbo Pascal Applications»): клон Turbo Vision,
  поставляется с FPC как пакет `fv` (`packages/fv` в
  `gitlab.com/freepascal.org/fpc/source`, зеркало `github.com/fpc/FPCSource`);
  Free Pascal IDE использует его. Происхождение: «backport of the PD C++ code»
  графической версии Леона де Боера обратно в текстовый режим.
- **Совместимость.** Установлено со слов проекта: «API compatibility with
  Turbo Vision, but not 100% complete». Конкретные расхождения в этом
  исследовании не перечислялись (**не установлено**; выяснить при D7 сборкой
  своих тестовых примеров). Названия модулей `app`, `drivers`, `views`,
  `dialogs`, `menus`, `editors`, `histlist`, `msgbox`, `stddlg`, `colorsel`,
  `validate`, `outline`, `gadgets` и др. — каталог `packages/fv/src`;
  объектные типы названы как в TV (**установлено** по именам файлов, по телу —
  не сверялось). Есть Unicode-варианты `u*.pas` (`uviews` и т.д.) — для всех
  целей, кроме `msdos` и `win16` (**установлено**, `packages/fv/fpmake.pp`).
  Клипборд — модуль `fvclip` (какие ОС поддерживает — не проверялось).
- **Цели.** Установлено (`packages/fv/fpmake.pp`): среди ОС для пакета есть
  `msdos`, `go32v2`, `win16`, `win32`, `linux`. То есть Free Vision заявлен для
  i8086-msdos; фактическая сборка не проверялась (**не установлено**; проверять
  в CI с кросс-компилятором 3.2.2).
- **Лицензия.** Установлено: `P.License := 'LGPL with modification, '` в
  `fpmake.pp`; wiki: LGPL 2.1 с исключением для статической линковки
  (library exception FPC). В заголовке `views.inc` отдельно: «Interface
  Copyright (c) 1992 Borland International», «Copyright (c) 1996–1999 by Leon de
  Boer», «THIS CODE IS FREEWARE» (с дисклеймером) — то есть и у Free Vision
  есть слой, чья чистота зависит от того, что интерфейс не является
  защищённым выражением; это обычная оговорка FPC, но её надо знать при
  выборе «опереться на FV» (**предположение** о юридической чистоте не
  делается).
- **Подходит ли как основа D7.** Предположение: да как для сборки FPC, так и
  как сторона, куда можно отдавать изменения (upstream в FPC); оговорки —
  64 КБ на модуль и размер FV на 16 бит (не проверено) и отсутствие
  Unicode-вариантов на `msdos`. Решение — за D7, после сборки тестового
  примера на FV под i8086-msdos в CI.

## 5. Инструменты сравнения кода

**SIM Дика Груне** (`https://dickgrune.com/Programs/similarity_tester/`).

- **Установлено** (скачан `sim.zip`, SHA-256
  `439b3ca5b0d80adaa5875905b5d56f0595f9c4cf7dab5d214c9b96a7bedfc6fe`; README,
  `Makefile`, `sim.1`): версия 3.0.5 от 2024-02-07; проверяльщики для C, C++,
  Java, **Pascal (`sim_pasc`)**, Modula-2, Lisp, Miranda, 8086 assembler и
  текста; лицензия — BSD-подобная (3 пункта; `LICENSE.txt`: Copyright
  1986, 2007 Dick Grune, Vrije Universiteit); сборка — gcc, flex, make
  (`make test`), готовые DOS-exe в `sim_exe.zip` (`SIM_PASC.EXE`).
- **Установлено:** параметры: `-r N` — минимальная длина общего участка в
  токенах (по умолчанию 24), `-p` — проценты, `-e` — каждый файл с каждым
  отдельно, `-n` — сводка по файлам, `-s` — не сравнивать файл с собой,
  `-R` — рекурсия по каталогам, `-w N` — ширина вывода; списки файлов
  разделяются `/` или `|` («новые» против «старых»); «секретная»
  опция `--` печатает вход так, как его видит проверяльщик (годится для
  проверки лексера). По `sim.1` и README: два фрагмента считаются похожими,
  если «differ only in layout, comment, identifiers, and the contents of
  numbers, strings and characters» — то есть переименование идентификаторов
  SIM ловит (все не зарезервированные идентификаторы сводятся к одному токену).
- **Установлено чтением `pasclang.l`** (не запуском: на этой машине нет flex,
  собирать SIM здесь не пытались): лексер понимает комментарии `{ }` и
  `(* *)`, строки в одинарных кавычках, отбрасывает директивы `#`; зарезервированные
  слова сопоставляются через `strcmp` **только в нижнем регистре** (`idf.c`) —
  `Begin`/`END` станут идентификаторами (в DN 1.51 есть 5 вхождений слова
  `Begin` и 4 — `BEGIN` против 8650 `begin`; для TV из BP7 надо
  проверить); слов `object`, `unit`, `uses`, `asm`, `inherited`, `constructor`,
  `virtual`, `implementation` в таблице зарезервированных **нет**: их считают
  идентификаторами. Комментарии `//` не распознаются.
- **Предположение, требующее проверки запуском** (пометить как риск D3/D5):
  правило строки `\'{StrChar}*\'` допускает escape-последовательности вида `\.`
  (как в C); в Паскале обратная косая — обычный символ. В DN 1.51 найдено
  **201 строк**, где строковый литерал кончается обратной косой перед
  кавычкой (пути вида `'…\'`), на них лексер может «проглотить» конец литерала. Если
  это подтвердится, обход — нормализация (а) и (б) из DN-PLAN до подачи в SIM
  (строки заменяются на `''`, регистр — в нижний, `//` — убрать).
- **Установлено:** в самом дереве FPC когда-то лежал `utils/sim_pasc`
  (зеркало `lz.rca2.net/downloads/fpc_251_17411/utils/sim_pasc/sim.html`, FPC
  2.5.1 — по результатам поиска; актуальность не проверялась).
- Вывод: для прохода 2 из D5 SIM годится как независимый внешний инструмент
  при условии предварительной нормализации; собственный детектор A (k-граммы с
  винноуингом) остаётся основным.

**Другие инструменты (проверено по их страницам):**

- **MOSS** (`https://theory.stanford.edu/~aiken/moss/`): Pascal поддерживается;
  доступ по регистрации через e-mail, скрипт отправляет файлы на **серверы
  Stanford**, результаты по случайной ссылке хранятся около 14 дней;
  некоммерческое использование. **Вывод:** загружать туда код DN/TV нельзя
  по правилам `DN-PLAN.md` (чужой код не покидает машину); в качестве
  проверки метода (на собственных контрольных данных, шаг 4 протокола) —
  допустимо.
- **JPlag**: Pascal нет (Java, C, C++, C#, Go, Kotlin, Python, R, Rust, Scala,
  Swift, JavaScript, TypeScript, LLVM IR, Scheme — wiki JPlag).
- **Dolos**: язык — любой, для которого есть парсер tree-sitter. **Не
  установлено**, есть ли подходящий парсер Pascal и справляется ли он
  с диалектом BP7.

## 6. Что это значит для D2–D7 и открытые вопросы

Установлено, на что можно опираться сразу:

1. Исходники DN 1.51: официальный архив (SHA-256 выше) идентичен GitHub-копии.
2. Лицензия RIT на собственный код: BSD-подобная с рекламным пунктом, в
   исходниках; TV-часть — по Borland, не разрешена в исходниках; в пяти
   файлах уведомление Borland сохранено прямо.
3. Родной компилятор — BP7 + TASM/TLINK, несвободные.
4. FPC 3.2.2 имеет готовый кросс-компилятор i8086-msdos; Free Vision заявлен для
   `msdos` в `fpmake.pp`.
5. SIM имеет Pascal-проверяльщик и свободную лицензию.

Открытое (для следующих шагов, не гадать):

- Собирается ли DN 1.51 каким-нибудь FPC (i8086-msdos): оверлеи, 428
  `asm`-блоков, размер кода — сделать пробную сборку в CI (отдельный PR,
  свободные инструменты, по правилам про CI), но не копировать DN в репозиторий:
  скрипт скачивает архив по SHA-256.
- Как запускать BP7 легально для D2: нужен каталог пользователя.
- Работоспособность `sim_pasc` на DN: собрать SIM в CI (gcc+flex), прогнать на
  контрольных данных (шаг 4 DN-PLAN) и опцией `--` проверить лексер на строках с
  обратной косой.
- Состав TV из BP7 для сравнения: у кого его брать (скачивать самому
  пользователю, по правилам не в репозиторий).
