## Открытые расследования

### VC 4.99.09 не доходит до панелей

Бинарники: `VC.COM` sha256 `85fcbb964af1aa120f4ad0c93922592e6c8345192c0ff809dc4b69e2934d7661`,
`VC.OVL` sha256 `a25e43f8b861edcf411797f407ffb7016702c2c7f070584970756a916ef62fd9`
(релиз `latest-build` `ddanila/vc` на 2026-10-01); исходники —
`versions/4.99.09`. Прогоны — в GitHub CI (временный workflow на ветке
`diag/run-vc499`): `GO2DOS_EXEC_TRACE=3000 go2dos -headless -trace ... ./VC.COM`,
затем с `GO2DOS_WATCH`. Сегмент PSP `VC.COM` — `0156`, оверлей — `01C2`
(его код — `01D2`); адреса детерминированы, но зависят от версии go2dos.

**Шаг 1 (что узнали).**

- **Установлено** (исходники). `VC.COM` запускает `VC.OVL` через `EXEC 4B00h`
  (`LoadOvlRAM`, `VC.ASM`), передав в хвосте команды блок `OvlPrm`: длина,
  `0`, `VcID`, далее far-указатель `OvlPrmPoint = StartMain` (смещение из
  ассемблера, сегмент — `CS` на `Init86`). Оверлей (`VCOVL.ASM`, `Start`)
  сверяет хвост, записывает по этому указателю свой адрес входа `Init00`,
  переделывает свой MCB и выходит через `4C00h`. Затем `VC.COM` выполняет
  `CALL DS:StartMain` (`VC.ASM`, `Exec10`).
- **Установлено** (трасса, CI-прогон 36802438760). `StartMain` лежит в
  `VC.COM` по смещению `010Fh` (линейный адрес `0166F`): так в хвосте EXEC
  (`tail=0156:014F [0B 00 56 56 56 30 30 39 0F 01 56 01 0D]`) указатель —
  `0156:010F`. `VC.COM` не перемещается.
- **Установлено** (`GO2DOS_WATCH=0156:010F/4`, прогон 36802764975). Запись по
  `StartMain` делает оверлей: `0166F: 00 -> 82` и `01670: 00 -> 00` командой
  `01D2:0033` (`MOV ES:[DI],OFFSET Init00`), `01671: 00 -> D2`, `01672: 00 -> 01`
  командой `01D2:0038` (`MOV ES:[DI+2],CS`). То есть `StartMain` = `01D2:0082`
  = `Init00` оверлея — запись корректна, до записи поле было нулём.
- **Установлено** (трасса). Оверлей завершается `4C00h` из `01D2:006C` с
  `DS=0DAD` (сегмент данных оверлея: `MOV DS,CS:SubsSeg` в `01D2:0059`),
  `ES=0156`, `BX=9E2E`. go2dos возвращает управление в `0156:052F`
  (после `INT 21h` родителя) с `SS:SP` родителя, но регистры остаются
  дочерними: `DS=0DAD`, `ES=0156`, `BX=9E2E`, `SI=0098`, `DI=010F`.
- **Установлено** (трасса, строки `exec` после возврата). `VC.COM` не
  перезагружает `DS` (после `INT 21h` в `LoadOvlRAM` идёт `CLD; JNC; RET`, дальше
  `Exec09` и `Exec10` обращаются к `DS:StartMain`, `DS:rLocation` и т.д.) и на
  `0156:0361` выполняет `FF 1E 0F 01` = `CALL DS:[010F]` с `DS=0DAD`. Читается
  слово не из `VC.COM`, а из сегмента `0DAD`, управление уходит на
  `01B5:4048` — не в `Init00`. Так же `Init00` ни разу не вызывается, `4Ah/48h`
  в трассе нет.
- **Установлено** (исходники MS-DOS 4.0, MIT, `microsoft/MS-DOS`,
  `v4.0/src/DOS/CTRLC.ASM`, `reset_return`, и `DISP.ASM`, `restore_world`).
  При завершении дочернего процесса DOS берёт стек родителя (`PDB_user_stack`)
  и `restore_world` восстанавливает с него `AX, BX, CX, DX, SI, DI, BP, DS, ES`
  — регистры родителя на момент его `INT 21h`; флаги при этом — `F202h`.
  go2dos (`endChild`) восстанавливал только `SS:SP`, `CS:IP` и флаги.
- **Установлено** (эксперимент, ветка `fix/exec-restore-registers`, прогон
  36802691593). Если родитель получает регистры назад, `CALL DS:StartMain`
  идёт на `01D2:0082`, `Init00` вызывает `4Ah`/`48h`, VC рисует рамки панелей
  и строку клавиш (`screen1.txt` артефакта). Следующая остановка —
  `INT 21h AX=440Dh CX=0866h BX=3` (generic IOCTL, «get media ID») из
  `0DAD:753D`: это новый, отдельный вопрос.

**Шаг 1: чего не знаем.**

- **Предположение.** Прежние наблюдения (экранная процедура в `0DAD` с `ES=0`,
  чтение `0000:0D6D`, `INT 10h AH=FFh`) — следствие вызова `01B5:4048`, а не
  самостоятельная причина. Прямо не проверено, кроме того, что при
  восстановлении регистров этот путь больше не достигается.
- **Не установлено.** Что делают реальные DOS 3.2+/FreeDOS/DOSBox-X с `AX` и
  флагами после EXEC. Проверен только MS-DOS 4.0 (флаги `F202h`, `AX` — из
  кадра родителя, т. е. `4B00h`); в `LoadOvlRAM` после `INT 21h` проверяется
  только CF (`JNC`), он у нас сброшен; остальное не проверялось.
- **Не установлено.** Нужно ли это NC и другим программам (вероятно: регистры
  после EXEC сохраняет DOS, не программа) — проверит владелец копии.

**Шаг 1: как узнать дальше.**

- Исправление предложено отдельным PR `fix/exec-restore-registers` (юнит-тест
  `TestExecRestoresRegisters`); решение — за владельцем.
- Следующий барьер — `INT 21h AX=440Dh` (`CL=66h`, get media ID): сверить с
  RBIL и `VCSUBS.INC`/`VC.ASM`, затем реализовать или ответить как «не
  поддерживается» по документации; после этого — повторить сбор по следующему
  барьеру (трасса `GO2DOS_EXEC_TRACE`, дамп).

**Инструменты** (добавлены для этого расследования; переменные окружения, чтобы не
менять флаги `cmd/go2dos`): `GO2DOS_WATCH=SEG:OFF[/LEN],ЛИНЕЙНЫЙ[/LEN]` (как
`-watch`, плюс `SEG:OFF` и длина в байтах, шестнадцатеричная);
`GO2DOS_EXEC_TRACE=N` — после каждого старта и возврата EXEC записывать в
трассу следующие N выполненных инструкций (`call="exec"`: адрес, байты,
регистры); трасса EXEC теперь включает блок параметров, хвост команды, PSP и
стартовые `CS:IP`/`SS:SP` потомка. Строки `exec` не попадают в кольцо
последних вызовов дампа.

## CPU

- **Установлено.** SingleStepTests 8088 v2: проходят все тесты статусов
  normal/undocumented/alias, кроме 60–6F, C0/C1, C8/C9 — у нас это команды 80186.
- **Предположение.** Команды 80186 тестами не покрыты; нужен набор тестов
  80186 (или 80286 в real mode) с поправкой на различия.
- Префиксы 66h/67h и 0Fh-команды 286+ — fail fast.

## BIOS и устройства

- **Решение.** Обратный ход луча (порт 3DAh) моделируется по числу чтений:
  «кадр» — 256 чтений, первые 24 — кадровый ход (биты 0 и 3), далее строчные
  импульсы. Модель по реальному времени зависала в цикле VC 4.99.09, который
  ждёт 10 подряд чтений с битом 0 (установлено дизассемблированием).
- **Решение.** Порты без устройства: чтение FFh, запись игнорируется, первое
  обращение к каждому порту пишется в трассу. Это не fail fast — пересмотреть,
  если станет мешать диагностике.
- **Решение.** `INT 33h`: мыши нет (сброс возвращает AX=0), остальные функции —
  без эффекта.
- **Предположение.** Таймер идёт по часам хоста (18,2 Гц), поэтому прогоны не
  детерминированы во времени. Для тестов это пока не мешает: сценарии ждут
  текста, а не времени.
- **Решение.** Код отпускания клавиши синтезируется сразу после нажатия;
  модификаторы в `0040:0017` выставлены только между ними. Символы вне ASCII
  приходят со скан-кодом 0, как при вводе через Alt+цифры.

## DOS

- **Установлено.** VC 4.05 проверяет DESQview через `INT 21h AX=2B01h`
  (`CX='DE'`, `DX='SQ'`) и ждёт `AL=FFh` (неверная дата). Поэтому установка
  даты и времени валидирует аргументы как DOS; само значение игнорируется
  (часы хоста главнее).
- **Решение.** `INT 2Fh`: неизвестный сервис — регистры не меняются (ответ
  «не установлен» на проверки наличия), запись в трассу.
- **Предположение.** Свободное место (`36h`) — фиксированные числа (1 ГиБ из 2).
- **Решение.** Вывод в CON идёт прямо в видеопамять (телетайп BIOS), а не через
  `INT 29h`/`INT 10h`; программы, перехватывающие их ради вывода DOS, этого
  не увидят.
- **Решение.** Нет `COMMAND.COM`: `COMSPEC` указывает на несуществующий файл, и
  команды из командной строки VC/NC не выполнятся.
- **Решение.** LFN (`71xx`) отвечает «не поддерживается» (`AX=7100h`, CF=1).
- Порядок алиасов `~N` детерминирован: имена каталога сортируются, точные 8.3
  имена получают приоритет.
